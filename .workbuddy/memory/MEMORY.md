# mybuddy 项目长期记忆

## 用户偏好（2026-09-19 确立）

- **不接受反复手工校正**：遇到"列表与实际不符"这类需要周期性人工对账的问题，用户明确表示「不能每次都靠你来执行」。
  倾向一次性自动化或代码级根治，交付物优先做成**可自助运行的脚本/工具**，而不是每次让 AI 手工改配置。
- 接受"先改配置验证、再决定是否改代码"的渐进路线，但会主动追问根治方案。
- **disabledModelIds（历史禁用条目）是用户有意配置的**（2026-09-20 已两次强调）：不要把它当垃圾/问题，
  不要再反复建议"清理失效禁用条目"。提及 provider 状态时直接跳过这一项。
- **多源一致的数据 > 单点实测**（2026-09-20 用户纠正）：曾试图用实测档位推翻 models.dev /
  openrouter / pi.dev 三个目录源的一致结论，被用户制止（「3 个以上目录都这么说，肯定是对的」），
  随后自证实测噪声极大（同档位连跑三次结论相反）。判据：看源的数量、一致性、稳定性；
  单点实测的噪声可能大于它想纠正的偏差。已验证过的多源一致数据不得被单点观测推翻。
- **不要跨 provider 复用凭证**：Zen 与 Go 是各自独立的订阅/服务，模型不通用。
  验证某 provider 能否用某 key，**必须实测一次真实 completion**，不能只看 `/models` 列表返回 200
  （列表端点常不校验订阅与路由前置条件）。2026-09-20 因此误配过 opencode-go，已撤回。

## 模型配置子系统要点

详见 `2026-09-19.md`。一句话：**模型列表 = 平台目录 × 已认证 provider，缺「账号已授权」这一维**，
导致 OpenCode Zen 这类"目录大、授权小"的 provider 出现大面积不可用模型。
