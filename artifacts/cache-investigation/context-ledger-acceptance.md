# 增量证据与 Memory 引用恢复：实现及验收

版本：0.1.78。生产实现位于 `src/main/agent/EphemeralContextProjection.ts`；本次不改变 Pi 工具结果、工具激活和原生压缩的所有权。

## 已实现

- 每轮请求状态与历史证据分离。普通轮次结束只释放执行状态；证据正文在原始用户条目位置逐字回放，每轮追加固定的短版本清单。
- Memory 投影返回逐来源证据块。按来源、版本、实际内容去重，变化时追加新版本。相同来源的预算变小时复用已投放片段，不重新裁剪历史。
- L1 引用只持久化来源版本、渲染参数、哈希、原始锚点与权限依赖。重新打开时用真实 Memory 历史还原并校验；未知渲染版本、内容哈希不符、历史版本缺失时阻止发送。
- L2/L3、项目笔记、资料目录等非历史来源保留于内存。重新打开时显式记录一次上下文重建边界，不把时间戳伪装成可恢复历史。混合上下文中，只要前面的非历史正文丢失，就不能保证整个前缀恢复。
- 资料库仍提供短引用和 `library_read`，不自动重复注入整篇资料。
- 权限检查覆盖全部历史依赖，包括原生压缩摘要、切换分支生成的摘要及其独立分支副本。当前版本清单不是权限证明。
- 当前轮的便签更新检测与历史访问权检查分离。保存原始项目资源、附件和固定资料的访问描述，重启后仍校验原始绑定。
- 模型调用门禁扩展到原生压缩和分支摘要；鉴权或排队之后再次检查撤销。
- 全量测试启动器补上 `windowsHide`，防止 Windows 下每项 pnpm 测试弹出终端。

## 自动回归

`test:context-ledger` 使用真实 AppDatabase、MemoryService、Pi SessionManager/会话/工具循环/分支/压缩、产品投影及模型调用门禁；供应商回复为离线脚本，通过真实 Responses 序列化器检查 payload，禁止网络。

覆盖：

1. 相同资料跨轮无重复；版本更新只追加；L1 会话重开后前缀不变。
2. 正文标记不进入持久化引用；不将此结果误解为派生事实从不落盘。
3. 实际运行中的请求中断后继续；重复的用户文本和时间戳不会串锚点。
4. 普通分支不回放另一分支的未来证据；带摘要的分支及其独立副本保留撤销依赖。
5. 原生压缩后补齐当前证据，压缩后重新打开仍稳定。
6. 请求初次放行后、payload 生成前撤销来源，实际门禁阻断发送；摘要请求也被阻断。
7. 非历史来源在预算降低时保持旧字节；重新打开只建立一次新边界；之后继续保持稳定。
8. 历史版本缺失、渲染版本不支持、哈希损坏及恢复后的权限丢失均阻止发送。

首次完整默认门禁通过 **252/252**，没有更新失败基线。另通过缓存边界矩阵、图像历史、原生自主执行、项目与空间便签测试。测试启动器的隐藏窗口改动通过语法检查及聚焦门禁。

## 保留的边界

- 撤销阻止后续请求，并提示新建任务以重建有效上下文；没有实现对既有助手回复、工具结果、磁盘会话或摘要的自动事实擦除。
- 非历史来源的正文不额外落盘，重启时可能损失一次缓存。只有有效上下文的全部必要证据都能恢复，才可能保持整个历史前缀。
- 明确的分支切换、压缩、工具或模型配置变化仍可能构成缓存边界。
- 内存中按有效上下文保留正文，压缩后释放失去锚点的正文；权限依赖继续保留以保护摘要中的派生事实。
