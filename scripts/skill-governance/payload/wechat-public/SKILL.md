# wechat-public — 微信公众号链接一键解析

> 下次人类指挥官发 `https://mp.weixin.qq.com/s/...` 链接，本技能自动接管，按四步流水线完成解析与提炼，无需重复说明。

## 何时触发

*   消息中包含 `mp.weixin.qq.com` 链接（`s/xxx`、`s?__biz=` 均可）；
*   用户说“讲了什么”“总结一下”“解析这个公众号”“提炼要点”“转成简报/Word”且上下文有公众号链接；
*   用户发公众号截图/图文并要求提取文字时，与 `npu-ocr` 协同（本技能主流程，OCR为兜底）。

## 工作流（严格按序，4步）

### 第1步：服务端直抓（快路径）

```text
# readable 优先，拿正文
fetch_content(url, mode="readable")
# 若被拦截，再试 raw 看 meta 兜底
fetch_content(url, mode="raw")
```

*   成功：直接拿到标题、正文、发布时间、作者、封面图。
*   失败特征：返回 `环境异常，完成验证后即可继续访问` 或正文为空但 `og:title` 存在 → 判定为反爬拦截，进入第2步。

### 第2步：浏览器真人渲染（主路径，已实测）

```text
browser_exec(action="navigate", url="<公众号链接>")
browser_exec(action="read")
```

*   用 MyBuddy 内置浏览器以真实用户身份打开，等待JS渲染完成。
*   `read` 自动提取 `innerText`，获得完整正文（本次实测 mp.weixin.qq.com/s/XfGIt5m0ZYPiUgJhZnwuow 全文约3500字，一次成功）。
*   同步提取：`title`、`author`、`publishTime`、`og:image`、`biz/mid/sn`。

### 第3步：清洗与结构化

1. 去噪：移除“阅读原文”“赞赏”“留言”“小程序”等无关UI文本。
2. 抽要素：标题、作者、发布方、发布时间、活动时间/地点、人物及职务、核心观点/致辞要点、流程/路线、历史背景、后续预告、素材来源。
3. 校核：人物职务、时间、地点必须能在原文中找到原句；不确定标“原文未提及”，禁止编造。

### 第4步：按“日常办公”交付

**表达底线（强制）：**
*   先用一段话讲清“结果是什么、对读者意味着什么”，再展开细节；
*   小标题+短段落，一段只说一件事；关键对比用表格；
*   关键事实带出处（链接或文件名）；不确定、查不到就明说。

**输出模板：**
```markdown
一句话结论：[结果+意义，1句]

来源：[标题] [作者/发布方] [发布时间] [链接]

1. 基本信息（主题/时间/地点/发布信息）
2. 谁来了（表格：人员|身份）
3. 要点提炼（致辞/核心观点分点）
4. 流程/路线（表格或序号）
5. 背景/渊源（简洁）
6. 后续预告
7. 使用提醒（局限与引用建议）
```

*   默认在聊天中直接输出提炼；若用户要求存档，同步写入任务工作区 `wechat_文章标题_提炼.md`，必要时用 `officecli` 转 `docx`。
*   全程保留原文链接作为出处。

## 兜底分支

*   若 `browser_exec read` 仍返回验证页/空文本 → 判定为强验证（需扫码/登录/滑块），停止重试，告知人类指挥官并引导：
    1. 请发文章截图 → 调用 `npu-ocr` 识别（`OCR_NPU_CLI.exe --input_path`）
    2. 或复制粘贴正文 → 直接进入第3步
*   若链接为合集/音频/视频号 → 说明类型并提取可得的标题与描述，不伪造正文。

## 已知坑（2026-08-27 实测）

1.  **环境异常页**是正常反爬，不是文章被删，切到浏览器即可。
2.  `raw` 源码约300万字符，前6万字符多为JS包，需用 `browser_exec read` 而非分页读源码。
3.  正文末尾会混入“赞赏作者”“留言”“小程序”等UI噪声，清洗时需截断于“素材来源/排版”之后。
4.  `publishTime` 有时仅显示“2026年8月27日 11:14”，无秒级，需原样保留。
5.  图片为 `mmbiz.qpic.cn` 外链，聊天中可直接引用，存档时需说明为外链非本地下载。

## 强制验证（每次执行后必做）

1.  **标题一致性**：`browser_exec` 返回的 `title` 与 `og:title` 一致；
2.  **正文非空**：`read` 文本长度 >500字且包含文章标题关键词；
3.  **关键要素可回溯**：表格中的人名、时间、地点均能在正文中找到原句；
4.  **出处完整**：回答中包含原文链接与发布方/时间。

## 调用示例

*   人类指挥官：`https://mp.weixin.qq.com/s/XfGIt5m0ZYPiUgJhZnwuow 讲了什么`
    → 自动执行：`fetch readable` → 拦截 → `browser navigate+read` → 清洗 → 按模板输出松溪站提炼（含8月22日大布村、四点巡游、揭牌、下两站预告）
*   人类指挥官：`帮我把这个公众号转成Word简报`
