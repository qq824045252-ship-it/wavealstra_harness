# 资料按项目和工作空间管理

## 产品入口

账户菜单不再提供聚合全部资料的「资料库」入口。项目的长期资料在「项目 → 资料」管理，工作空间的长期资料在「工作空间 → 资料」管理。「独立任务」标题旁的「个人资料」保留原个人文档和没有归属项目的历史资料，不改变原有条目 ID、文件位置、版本和引用。

菜单的「文件」改为「任务成果」，仍展示任务生成的产物。工作空间内的「文件」继续表示真实磁盘工作目录。导入长期资料会保存受管副本，不会把整个工作目录自动导入。

局部资料管理器共用创建、导入、阅读、文本编辑、文件夹组织、重命名、移动、收藏、删除和任务成果保存流程。旧资料链接仍由 `LibraryPage` 适配到来源所属的范围，不能用一个旧导航目标扩大当前资料管理器的范围。

## 归属与引用

底层仍只有一套 Library 存储、索引和预览协议。一份资料只有一个来源位置；引用不复制文档，也不授予修改源文档的权限。

| 来源 | 管理位置 | 默认写入 |
| --- | --- | --- |
| 项目资料 | 对应项目的资料页 | 绑定项目的任务默认保存到项目 |
| 工作空间资料 | 对应工作空间的资料页 | 无项目、但绑定工作空间的任务默认保存到当前空间 |
| 个人资料 | 独立任务旁的个人资料入口 | 无项目、无工作空间的独立任务默认保存到个人资料 |
| 没有归属的历史资料空间 | 个人资料入口的历史位置 | 保留原位置，用户可直接整理和显式引用 |

`LibrarySpaceDto.projectId` 与新增的 `workspaceId` 互斥。工作空间资料位置在首次需要写入时惰性创建，一个工作空间只有一个自有资料位置。旧项目已有多个资料位置时保留这些位置，默认选择稳定排序的第一个，用户仍可选择项目内其他位置。

新增 `library_spaces.workspace_id` 使用同版本数据库的幂等增量补列和唯一索引。**本次不提升 `CURRENT_DATABASE_SCHEMA_VERSION`，不触发数据库版本不兼容重建。** 对实际缺少该列的旧结构执行升级和重启，测试验证旧个人文档、项目文档、版本和引用保留。

工作空间资料页分为：

- **本空间资料**：在本处创建、编辑和整理。
- **本空间引用**：用户显式添加其他位置或某个文件夹的引用；文件夹包含其后代。
- **继承自父级**：当前祖先工作空间的自有资料和显式引用；在本处只读。

引用项目资料不会绕过项目范围：任务必须属于同一项目才可使用。用户管理界面可以查看来源、添加引用，但 Agent 始终重新校验任务所属项目。

## Agent 的统一资料范围

以下路径共用 `resolveTaskScope`，不再各自拼接不同的个人、项目、工作空间范围：

- `library_list`、`library_search`、`library_read` 以及写入工具。
- 项目知识检索与读取。
- Workspace Locator 的词法、分块和语义检索。
- 任务目录、附件说明、上下文投影和历史证据访问复核。
- 模式预览：已有任务按数据库归属，新任务预览按明确选择的项目和工作空间。

任务可读范围为当前项目资料、当前及未归档祖先工作空间资料、工作空间显式引用、当前任务附件与项目固定引用的并集。未明确引用的个人资料和同级空间资料不自动进入该范围。无项目、无工作空间的独立任务默认可使用个人资料。

几个边界必须同时成立：

1. 真实任务 ID 从数据库重新解析；客户端提供的旧项目值不能覆盖任务归属。未知任务返回空范围，不回退到个人资料。
2. 引用单条文档只增加该条文档，引用文件夹只增加该文件夹子树，不能放大为整个资料位置。
3. 范围过滤发生在 SQL 候选查询之前，早于排名和条数限制；大量其他范围的命中不能挤掉合法结果。
4. 修改仅允许当前项目或当前工作空间的自有资料。父级继承、外部引用与任务附件只提供读取权。
5. 项目归档后，项目任务不能改为向个人或工作空间资料写入。归档来源本身也不能写入。历史显式引用仍可读取，以便回看。
6. 只读调用在创建默认资料位置前被拒绝，不留下空位置。
7. Locator 可显式临时查询未归档的直属子空间。读取对应结果需在 `library_read` 携带同一个 `explicitDirectChildSpaceId`，不持久扩大默认范围，不允许跳到兄弟或孙级空间。
8. 语义检索或异步文档提取等待期间取消引用、移动来源或删除任务，返回结果前会重新复核范围。

## 编辑与生命周期

文档编辑草稿按来源和条目 ID 保存在当前会话中，切换资料、资料页签时提供保存或放弃选项。导航离开后重新打开可恢复未保存草稿；如果源资料已有更新，会提示核对。明确保存、放弃或者手动改回原内容后清除草稿。

| 操作 | 结果 |
| --- | --- |
| 取消空间引用 | 只删除关联，原资料保留 |
| 取消项目常用资料 | 只删除固定引用，原资料保留 |
| 从任务成果保存资料 | 复制为受管资料，保留原任务产物和来源信息 |
| 删除原资料或文件夹 | 需要确认；删除源内容和相应关联 |
| 删除仍有自有资料的工作空间 | 拒绝，提示先处理资料；不先清理任务或工具 |
| 从归档管理删除包含资料的工作空间树 | 先检查整树；被阻止的树不进入任务和工具清理流程 |
| 删除已经清空的工作空间 | 清理空自有资料位置及其关联；被引用的外部源资料保留 |

项目原有的删除生命周期保持一致：删除项目会删除该项目拥有的资料。工作空间对该项目资料的引用不会生成一份独立副本。

## 验收目标与测试入口

| 验收目标 | 主要自动化覆盖 |
| --- | --- |
| 旧库保留数据、归属惰性且幂等、写入默认位置正确 | `test:library-owner-scope` |
| 自有/引用/继承展示和祖先资料范围正确 | `test:workspace-materials-view` |
| 直接传条目 ID、空间 ID 不能绕过当前任务范围 | `test:library-extension`、`test:project-knowledge` |
| 单条引用和文件夹引用不扩大范围；先过滤后限额 | `test:workspace-resource-locator`、`test:workspace-chunk-r2` |
| 目录、附件和上下文投影一致；改绑和取消引用立即生效 | `test:library-workspace-context` |
| 原文件、版本、来源和引用生命周期保留 | `test:library-domain`、三个 Library transaction suites、`test:knowledge-lifecycle` |
| 普通与归档工作空间删除不在失败前清理其他内容 | `test:library-owner-scope`、`test:archive-deletion` |
| 项目和工作空间就地管理、只读引用与编辑草稿 | `test:scoped-library-manager` 及项目/工作空间 GUI 夹具 |
| 类型、生产构建与其他功能无回归 | `typecheck`、`build`、`test:all` |

实际桌面验收应检查：项目内新建和导入、CSV/Markdown/HTML 编辑、文件夹移动、工作空间自有资料、父级继承、引用文件夹子树、取消引用保留原文、个人历史资料入口、任务成果保存、归档只读和删除前置检查。GUI 夹具使用临时配置和测试数据，不读取真实用户资料。

生产构建和 headless 门禁不能替代真实 Electron 桌面与 Windows 安装包验收。每次交付报告应分别记录这些验证的实际执行情况。
