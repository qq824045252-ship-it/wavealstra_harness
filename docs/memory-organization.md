# AI 记忆整理

记忆设置页提供「整理全部记忆」，浏览列表的搜索和范围筛选不会缩小整理范围。默认列表显示有效记忆，原始证据、关联和修改历史在详情中展开。

## 整理与应用

- 扫描全部 `active` 条目，按完整的作用域绑定集合、记忆类型和有效期分组。已归档、回收区任务和不在有效期内的条目计入跳过数量，不改动。
- 在每组内按文本近邻安排有大小限制的批次，AI 检查正文，提出合并、精简、拆分、退出召回或冲突。每批必须确认检查了所有输入 ID。禁止跨范围合并或把来源不明的 ID 写回。
- 普通事实、决定和明确要求不会自动退出召回。退出召回仅允许非显式的临时进度；冲突保留原样，打开来源后手动判断。
- 预览不改变事实。批量应用在一个数据库事务中完成：保留一个原有 ID，聚合证据，旧重复条目标记为 `superseded`，拆分的新增条目复制原有范围，记录关联和修订历史。
- 应用前重新检查来源内容、范围、证据、时间和归档状态。任一来源已改变时拒绝整个应用，避免覆盖其他对话刚写入的事实。
- 撤销恢复原来的正文、状态和证据；拆分新增条目退出召回。后续修改过的记忆不能被撤销覆盖。派生场景与技能来源按现有失效规则重新检查，不恢复旧的派生结果。

## 进度与重复运行

`memory_organization_runs` 是当前 schema 下的幂等新增表，不提升会导致数据库重建的 schema 版本。任务、输入快照、批次进度和撤销依据持久化于现有数据库。暂停会中止模型请求；进程退出后可继续未完成的批次。硬删除来源记忆会同时撤销包含该来源的整理预览和备份，未完成的响应不能重新写回它们。

已检查且没有变化的分组使用内容指纹跳过模型调用。存在新事实或修改时重新检查受影响的分组；尚未解决的冲突不作为已清理的基线。分批检查完整覆盖记录，但 AI 的语义判断和跨批相似主题的聚合仍需通过实际使用评估，不能以条数减少代替正确性。

日常提取也改为先按当前内容检索相关旧记忆，再让模型决定新增或更新；落库前的精确去重覆盖整个目标范围，不再限于 80 条。相同正文换标题不会再次新增。

## 验证

- `pnpm -s test:memory-organization`：超过 500 条的全量覆盖、所有范围、共享绑定、归档跳过、预览／应用／撤销、证据、重复运行、并发修改、事务回滚、暂停恢复、硬删除撤销、拆分、冲突和增量去重。
- `pnpm -s test:memory-ui`：在真实 Electron 中检查页面交互、明暗主题和窄窗口布局。
- `pnpm -s test:memory-organization-desktop`：默认检查 dev 构建。也可运行 `node scripts/memory-organization-desktop-test.cjs <MyBuddy.exe>` 检查实际安装包。使用独立临时 HOME、数据库和本地 HTTP 模型，不读取真实账号凭据；验证从 UI 发起、真实模型请求、进程重启后的预览恢复、应用和撤销。
