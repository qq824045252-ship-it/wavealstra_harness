# 欢迎三模式 · 验收后做什么 / 下一步怎么排

> 本文固化「验收后工程收口」与「四项 backlog 是否当下一步」的共识。  
> **核心结论**：四项增强**不是**验收后的固定下一刀；产品打磨优先于评测基建。

---

## 1. 验收通过后要做的（工程收口）

与功能 backlog 分开：验收通过后优先做交付流程，而不是立刻开新功能。

1. **提交代码**（若尚未 commit）  
   - 范围：ModeProfile、设置编辑、装配预览、D1 锁定、复制新任务、模式图标、技能过滤、tool hard 等  
   - 说明写清：仅新任务生效、任务内 mode 锁定、用户覆盖目录 `~/.mybuddy/modes/`

2. **推远程 / 开 PR**（按团队流程）  
   - 描述可引用 `fixtures/modes/README.md` 与本文件验收清单  
   - Review 重点：`PromptAssembly`、权限/工具 hard deny、任务锁定语义

3. **合并主分支**  
   - 有 CI 等绿；无 CI 至少本地：  
     ```bash
     pnpm typecheck
     pnpm test:mode
     pnpm test:expert
     ```

4. **文档收口**  
   - `STATUS.md`：三模式条目保持与实码一致  
   - `plan-welcome-modes.md`：主实施计划可标为 **已交付 / done**  
   - 用户向说明：模板在 **设置 → 场景模式** 改；覆盖路径 `~/.mybuddy/modes/`

5. **发版（可选）**  
   - `pnpm pack` / `pnpm dist`  
   - 升级说明：用户 `~/.mybuddy/modes/` **不被安装覆盖**

## 2. 验收时建议快速过的清单

| 检查项 | 怎么做 | 期望 |
|--------|--------|------|
| 设置编辑 | 设置 → 场景模式 → 改「目标」→ 保存 | 提示仅新任务生效 |
| 装配预览 | 点「预览装配」 | 分段可见；可复制全文 |
| 新任务生效 | 新建任务发一句话 | 语气/交付贴合该模式 |
| 旧任务不热更 | 改模板后再问旧任务 | 旧 session 不变（D1） |
| 锁定 | 有消息的任务改欢迎区 mode | 不能改掉该任务 mode |
| 复制换场景 | 任务 ⋯ → 复制为办公/编码/设计 | 新任务 + 对应图标 |
| 图标 | 侧栏顶层 + 空间内 nested | 均有模式小图标 |
| 场景 chip | 首页 chip 一点 | 输入框被填入 |
| 专家推荐 | + → 专家 | 本场景推荐靠前 |

自动化：

```bash
pnpm typecheck
pnpm test:mode
pnpm test:expert
```

## 3. 四项 backlog：是什么 / 替代 / 是否下一步

这些是计划里**刻意未做满或可选增强**，**不挡**当前产品闭环与验收。

| 项 | 是什么 | 现在有没有替代 | 建议是否「下一步」 |
|----|--------|----------------|-------------------|
| **Skill frontmatter `modes` 全面解析** | 从 `SKILL.md` 读 `modes: [working, coding]`，按场景过滤技能 | 已有：policy 的 prefer / demote / hide + 设置开关「技能按场景过滤」；代码**支持** `modes` 字段，但安装/扫描时**还没普遍写入/解析** | **可选中期**：技能变多、要精细控制时再做 |
| **suggestedModelId** | 某场景默认建议 / 自动选模型 | policy 里**已能写**；新建任务**不会**自动切模型 | **可选产品增强**：明确要「选办公就默认某模型」再做 |
| **resources/modes/** | 出厂模板放磁盘目录（随安装包），而不是 `mode-defaults.ts` | 已有：TS 种子 + `~/.mybuddy/modes/` 用户覆盖，设置里可改 | **低优先级工程重构**：除非要「不发版改出厂文案」或非开发改种子 |
| **mybuddy-bench / Harbor** | 官方 260 题评测框架（Docker + 数据集） | 本地有 `fixtures/modes` + `pnpm test:mode` | **不是产品下一步**；只有要对齐官方分数、做 agent 对比评测时才上 |

### 3.1 四项的边界说明

- **frontmatter `modes`**：属于技能元数据完备性；当前场景过滤已可用。  
- **suggestedModelId**：属于「场景 → 默认模型」产品策略；与模板编辑正交。  
- **resources/modes/**：只是种子载体迁移；用户可写层已解决「可编辑」。  
- **Harbor/bench**：研发评测专项，与侧栏图标、设置改模板**不是同一条产品路线**。

## 4. 更合理的「下一步」怎么排

### 4.1 若目标是 **产品继续打磨**（当前更像这个阶段）

优先顺序：

1. **真实使用反馈**（模板语气、锁定交互、图标是否够清楚）  
2. 需要时再做 **suggestedModelId 自动应用**（用户可感）  
3. 技能一多再做 **frontmatter `modes` 解析**  
4. **resources/modes/** 几乎可一直不做  
5. **Harbor / bench** 放研发评测专项，别进日常功能迭代  

### 4.2 若目标是 **对齐官方评测 / 发论文式对比**

才**单独开一条线**做 mybuddy-bench + Harbor。  
不要和「设置改模板、侧栏模式图标」捆在同一个迭代里。

## 5. 一句话

| 问题 | 答案 |
|------|------|
| 验收后默认下一步？ | commit → PR → 合并 →（可选）打包；用起来收集反馈 |
| 四项 backlog 是固定下一刀吗？ | **不是** |
| 哪项最不该现在做？ | **mybuddy-bench / Harbor**（除非明确要打分） |
| 哪项用户最有感（若要做增强）？ | **suggestedModelId 自动应用** |
| 哪项几乎可不做？ | **resources/modes/** 磁盘种子迁移 |

## 7. 验收不通过时的排查（附）

| 现象 | 优先查 |
|------|--------|
| 改了设置没感觉 | 是否**新任务**；旧任务本就不重载 |
| 想改任务模式改不了 | 符合 D1 → 用「复制为…任务」 |
| 图标没有 | 任务是否有 `welcomeMode`；历史任务默认 coding |
| 预览失败 | 主进程是否起来；控制台 IPC |
| 工具/技能不对 | 「技能按场景过滤」开关；policy soft/hard |
