# 悬浮菜单修复说明（右侧扩展栏 ☰ Flyout）

> 记录右侧扩展栏「☰ 悬浮菜单」的一次行为修复：**点击产物条目后收起菜单**，
> 以及悬浮菜单相关的代码结构说明。

---

## 1. 背景与现象

右侧扩展栏（产物面板）顶部的 ☰ 按钮会弹出一张悬浮菜单卡片（flyout），
内含「概览 / 工作空间文件 / 变更」切换与「产物」列表。

**修复前的不一致现象：**

| 操作 | 现象 | 用户评价 |
|---|---|---|
| 点击菜单里的「网页」（html 产物）条目 | 悬浮菜单消失 | 看起来正确 |
| 点击菜单里的「md 文件」等其他产物条目 | 悬浮菜单保持打开 | 不符合预期 |

用户预期：**点击产物链接（条目）后，悬浮菜单应当收起**——与产物类型无关。

---

## 2. 根因分析

### 2.1 核心事实：点产物条目本来就不会关菜单

`openArtifact`（`src/renderer/src/store/appStore.ts:1755`）只修改
`panelMode / activeArtifactId / artifactTabs / panelWidth / extensionView`，
**从不把 `extensionFlyoutOpen` 置为 false**。也就是说，对任意类型的产物
（html、md、code、pdf……），点击条目后菜单状态都保持打开。

点击条目不会触发"点击外部关闭"的原因：

- 菜单卡片位于 `.extension-menu-anchor` 锚点容器内；
- `ExtensionFlyout.tsx` 卡片根节点有 `onClick={(e) => e.stopPropagation()}`；
- `useDismissOnClickOutside`（`src/renderer/src/hooks/useDismissOnClickOutside.ts`）
  用 `event.composedPath()` 判断点击是否落在锚点内，落在锚点内不算外部，不关闭。

### 2.2 网页"看起来消失了"的真相：被原生视图盖住

网页（html）产物预览使用主进程的 **WebContentsView**（`src/main/artifact/ArtifactPreviewHost.ts`）。
Electron 中**原生视图永远渲染在 renderer DOM 之上，z-index 无效**——
这正是 `HtmlArtifactView` 的 `overlayOpen` 参数存在的原因（菜单打开时需先隐藏原生视图，
否则菜单会被网页盖住）。

时序（点击「网页」条目的那一刻起）：

1. `openArtifact` → 面板切到 html 预览 → `HtmlArtifactView` 挂载 → `api.preview()` 加载 WCV；
2. 挂载时 `overlayOpen` 的 effect 调用一次 `api.hide()` 隐藏 WCV——
   **该 effect 依赖是 `[overlayOpen]`，只执行一次**；
3. 但 `reportRect` 有四个触发源，每次都会 `api.setRect`：
   - 挂载时立即调用；
   - 挂载后 **220ms 的 `lateSync` 定时器**（`HtmlArtifactView.tsx`）；
   - **面板宽度 `transitionend`**（`.artifact-panel` 有 `width 0.2s ease` 过渡，
     打开 html 时面板从窄轨 280px 跳到 58% 主区宽，必触发）；
   - `ResizeObserver` / 窗口 resize；
4. 主进程 `setBounds`（`ArtifactPreviewHost.ts`）**无条件 `setVisible(true)`**，
   把 `hide()` 的效果顶掉；
5. 于是点击条目约 200–300ms 后，WCV 重新显示，**把还开着的悬浮菜单卡片整个盖住**
   ——看起来就是"菜单自动消失（正确）"。

严格说：此时 `extensionFlyoutOpen` **仍然是 true**，菜单只是看不见了。

### 2.3 为什么 md 不消失

md 预览走 `ProgressiveMarkdownDocument`（`ArtifactPanel.tsx` 的 `ArtifactBody`），
**纯 DOM 渲染，没有原生视图参与**。菜单开着就是开着，没有任何东西能盖它，
于是如实保持可见——问题被"诚实"地暴露出来。

### 2.4 小结

> 网页的"正确"是巧合（WCV 遮盖假象），md 的"不消失"才是真实状态。
> 代码里从来没有"点产物关菜单"的逻辑，行为差异与产物类型无关。

## 3. 修复内容

**文件：** `src/renderer/src/store/appStore.ts`，`openArtifact` 入口（+2 行）：

```ts
openArtifact: (id) => {
  // 点击产物即收起右侧扩展栏悬浮菜单（钉住时保持打开，由 closeExtensionFlyout 内部判定）
  get().closeExtensionFlyout();
  set((s) => {
    // ...原有逻辑不变
  });
},
```

**为什么放在 `openArtifact`（store 层）：** 所有"点产物"的入口都汇聚到这里，
一处修改全路径生效：

| 触发路径 | 位置 |
|---|---|
| 悬浮菜单里的「产物」列表（本问题场景） | `OverviewView.tsx:14` |
| 面板顶部产物 tab | `ExtensionTopBar` 的 `onOpenTab` |
| 聊天气泡里的产物 chip / markdown 链接 | `FileBadge.tsx:70`、`Markdown.tsx:51` |
| 变更列表、文件记录表、文件页 | `ChangesView.tsx:32`、`FileRecordsTable.tsx`、`FilesPage.tsx:131` |

**为什么复用 `closeExtensionFlyout()` 而不是直接 `set({ extensionFlyoutOpen: false })`：**
`closeExtensionFlyout` 内部尊重"钉住"状态（pinned 时直接 return），
与 backdrop、click-outside 对 pin 的语义保持一致。

### 修复后行为对照

| 场景 | 行为 |
|---|---|
| 未钉住，点悬浮菜单里的产物（任意类型） | 菜单立即关闭 ✅ |
| 钉住后点产物 | 菜单保持打开（用户明确要求常驻）✅ |
| 菜单未开时点产物（聊天 chip、顶部 tab 等） | `closeExtensionFlyout` 为无害空操作（值未变不触发重渲染）✅ |
| 网页产物 | 菜单真关闭，不再依赖 WCV 遮盖假象 ✅ |

### 验证

- `tsc --noEmit -p tsconfig.web.json`：通过；
- `git diff`：仅 +2 行。

## 4. 悬浮菜单代码地图

### 4.1 状态（`src/renderer/src/store/appStore.ts`）

三个状态字段（初始化见 `appStore.ts:489-491`）：

| 字段 | 含义 |
|---|---|
| `extensionFlyoutOpen` | 悬浮菜单（☰ 弹出的卡片）是否打开 |
| `extensionFlyoutPinned` | 是否钉住（钉住后点外部不关闭） |
| `extensionMenuOpen` | 另一个小菜单：无产物 tab 时 ☰ 弹出的模式菜单（概览/工作空间/变更） |

相关 action（`appStore.ts:1755-1900` 区间）：

| action | 职责 |
|---|---|
| `openArtifact(id)` | 打开产物；**现在同时收起悬浮菜单（本次修复）** |
| `toggleExtensionFlyout()` | ☰ 按钮：开/关悬浮菜单；无产物 tab 时直接 return |
| `openExtensionFlyout(mode?)` | 打开悬浮菜单并按 `defaultFlyoutViewForArtifact` 决定视图 |
| `closeExtensionFlyout()` | 关闭悬浮菜单；**pinned 时 return（不关）** |
| `toggleExtensionFlyoutPinned()` | 切换钉住状态 |
| `showOverview()/showWorkspace()/showChanges()` | 切换视图；`extensionFlyoutOpen = hasFileTabs` |
| `closePanel()` / `closeArtifactTab()` | 关面板 / 关最后一个 tab 时顺带收起菜单 |

### 4.2 入口：`ExtensionTopBar.tsx`（面板顶部栏）

- ☰ 按钮：`showTabs`（有产物 tab）时开 `toggleExtensionFlyout`，
  否则切换 `extensionMenuOpen`；
- `.extension-menu-anchor` 是**点击外部判定锚点**（`flyoutAnchorRef`），
  悬浮菜单卡片挂在这个容器内；
- 两个 `useDismissOnClickOutside`：一个管悬浮菜单（`open && !pinned`），
  一个管小模式菜单；
- 产物 tab 行（`.extension-top-tabs`）在锚点**之外**——点 tab 本就会触发
  click-outside 关闭菜单，与本次修复形成双保险。

### 4.3 卡片：`ExtensionFlyout.tsx` + `ExtensionFlyoutContent.tsx`

- `ExtensionFlyout`：卡片外壳，根节点 `onClick stopPropagation`（防点外部判定），
  头部 = 模式下拉 + 钉住按钮，body = 子视图；
- `ExtensionFlyoutContent`：按 `extensionView` 分发三个视图
  （`OverviewView` / `WorkspaceFilesView` / `ChangesView`，均以 `floating` 模式渲染）。
- 关键 CSS（`global.css`）：`.extension-flyout-card`（absolute、`z-index: 220`）、
  `.extension-workspace-backdrop`（`z-index: 70`）。

### 4.4 内容视图

- `OverviewView(floating)` → `ArtifactRail(variant="panel")`：
  「产物」列表，条目 `onSelect → openArtifact`（本次修复的主路径）；
- `WorkspaceFilesView(floating)`：工作空间文件树，点文件走
  `openWorkspaceFile`（**不走 openArtifact，点文件不会收起菜单**——已知边界）；
- `ChangesView(floating)`：变更文件列表，点变更同样走 `openArtifact`。

### 4.5 关闭机制汇总

| 机制 | 位置 | 说明 |
|---|---|---|
| 点击锚点外（pointerdown 捕获） | `useDismissOnClickOutside.ts` + `ExtensionTopBar.tsx:59-64` | `open && !pinned` 时生效；Esc 也关闭 |
| 预览区 backdrop | `ArtifactPanel.tsx:223-228` | `extensionFlyoutOpen && !pinned` 时渲染全屏透明按钮，点击即关闭 |
| ☰ 再点一次 | `toggleExtensionFlyout` | 关闭并清掉 pinned |
| **点产物条目（本次新增）** | `openArtifact` → `closeExtensionFlyout` | 未钉住时收起 |

### 4.6 与 HTML 产物预览（WCV）的交互

- `HtmlArtifactView`（`src/renderer/src/components/artifact/HtmlArtifactView.tsx`）：
  `overlayOpen={extensionFlyoutOpen}`，菜单打开时 `api.hide()` 隐藏原生视图；
- `ArtifactPreviewHost`（`src/main/artifact/ArtifactPreviewHost.ts`）：
  `setBounds` 无条件 `setVisible(true)`——见下文遗留问题。

## 5. 已知遗留问题（未修复，记录在案）

**WCV 显隐竞态：** `setBounds` 每次都会 `setVisible(true)`，会顶掉 `hide()`。
本次修复后，未钉住场景（点产物 → 菜单真关闭）不再触发该问题；
但 **pinned + 切换 html 产物** 时，菜单保持打开的状态下仍可能被重新显示的
WebContentsView 盖住（`lateSync` 220ms / 面板宽度 `transitionend` / `ResizeObserver`）。

后续修复方向（如需要）：

- 主进程：`setBounds` 尊重一个"overlay 抑制"标志（`hide()` 置位后不得重新
  `setVisible(true)`，直到 `show()` 清除）；
- 或 renderer 端：`lateSync` / `transitionend` 回调里先检查 `extensionFlyoutOpen`
  再 `setRect`。
