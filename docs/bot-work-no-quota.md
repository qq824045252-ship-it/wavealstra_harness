# Work 无预算运行约定

2026-11-09：按用户要求，删除 Work 额度/预算模块。此前阶段设计中的共享额度、预算窗口与预算核对要求不再适用。

## 当前行为

- Work 不再保存或输出 token 预算、可用额度、预留、窗口或续期策略；团队创建也没有额度参数。
- 执行派发、协作、后续跟进、结果接收与关闭不以 token 用量为条件。原生结果缺少用量时，不新增预算阻碍，不等待账单才能结束已确认的执行。
- 供应商原始用量仍可用于遥测；不据此限额、收费、冻结额度或推断外部业务效果。
- `WorkBudgetService`、预算 DTO、预算控制命令、provider 预算准入/结算与新库中的预算存储均已删除。已移除命令返回无效请求，而非假装成功或返回无限额度。
- 本次不重建已经退役的审批或共享资源隔离。现有身份/工作区边界、宿主权威、外部效果核对、因果防环与团队并发逻辑不因移除 token 额度而改变。上下文/证据材料裁剪、原生 reasoning token 参数、供应商自身限流不属于 Work 额度模块。
- Work 请求保留逐次权限检查。隐藏的 HTTP/WS 重试不能绕过撤销授权；不支持该检查的供应商 SDK 仍按既有安全边界拒绝受约束请求。普通对话的供应商重试不变。

## 已有数据与升级

不提升数据库 schema 版本，避免现有不兼容版本处理流程备份后重建整个数据库。新数据库不创建 Work 预算表和预算列。

现有当前版本数据库的预算表、预算列与原始审计记录保留为惰性历史，不自动执行 DROP、批量清理或重写历史。旧版 `works.budget_json` 是无默认值的必填列时，新建 Work 仅为该列写入空对象；模块不读取、投影或执行其中的额度。旧授权 JSON 中的预算字段不再出现在当前授权投影中。

只忽略具有精确模块身份的旧预算 operational 阻碍和旧用量缺失阻碍。原记录不清除；包含未知外部效果引用的阻碍、其他 operational 阻碍以及审批/授权规则仍有效。

旧团队创建可能已写入成功但前端没有收到回执。客户端先保留原 operationId，通过当前用户范围内的只读 `get_by_operation` 找回原团队，不因删除旧额度字段而换一个操作身份重建团队。

## 回归入口

- `pnpm -s test:bot-work-no-quota`：无预算合同/新库结构、缺少用量仍可结算、旧数据保持不变、安全边界保留。
- `pnpm -s test:durable-provider-authority`：真实本地 HTTP 夹具的撤权、隐藏重试、并发隔离、compaction 与原始遥测。
- 前序 phase2/phase3、因果防环、团队、评审与 UI 测试继续覆盖各自业务边界。历史带日期的复核记录按当时结果保留。

验证只使用独立临时数据库和原生执行目录，不打开真实用户数据库。
