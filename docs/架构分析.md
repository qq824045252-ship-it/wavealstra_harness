## 1. 项目是什么

**MyBuddy 形态的本地桌面 Agent**：单机 Electron 桌面应用，把 [pi-coding-agent](https://github.com/earendil-works/pi-coding-agent)（pi SDK）包装成带完整 GUI 的 AI 助手。

- **聊天 Agent**：多任务/多空间会话、流式回复、思考过程、工具调用、危险操作审批
- **产物工作台**：Agent 写出的文件（代码/Markdown/HTML/PDF/Office/图片）在右侧面板预览，HTML 产物用原生 WebContentsView 完整渲染
- **专家体系**：可安装/导入/导出的单角色专家（Agent 型插件），支持 Private Skills 与统一 Runtime 装配；不提供静态专家团
- **技能市场**：官方 294 技能按需安装 + 本地市场
- **MCP**：配置管理 + pi-mcp-adapter 运行时（工具直接进对话）
- **自动化**：cron 定时任务（at/every/cron 表达式）
- **IM 网关**：Telegram（长轮询）/ 飞书 / 企业微信 / 微信公众号
- **长期记忆**：每轮对话后 AI 抽取 global/space 两级记忆
- **场景模式**：日常办公 / 代码开发 / 设计创意 三套 system prompt 装配

**核心设计理念**（贯穿全代码的几条主线）：

1. **壳与组件是壳，AI 只有 pi 一个后端**：`createAgentSession` 是唯一 Agent 运行时，Electron 只做 UI、持久化、调度、审批、产物预览
2. **主进程持有全部状态，渲染进程是纯消费者**：所有数据经 IPC 单向流出；渲染层只维护 zustand 内存态
3. **事件流单向管道**：pi 事件 → 主进程映射为 UI 补丁 → 广播到渲染层，渲染层只管"把补丁画出来"
4. **数据目录收敛在 `~/.mybuddy/`**：SQLite 存结构化数据，jsonl 存会话，文件系统存技能/专家/扩展

**两个关键的工程 hack**：

- `electron.vite.config.ts` 的 `shimNodeSqlite()` 插件：Electron 无 `node:sqlite`，但某些依赖会 `require("node:sqlite")`，插件在 resolve 阶段把该 id 指向 `src/main/shims/node-sqlite.ts` stub，并在 renderChunk 里把残留 `require` 替换为抛错 stub——保证打包不炸
- `pi-mcp-adapter` 无法直接作为 CJS 依赖消费（`import.meta.url`、exports 子路径不全），用 `scripts/build-mcp-adapter.mjs` esbuild 预打包成 `src/main/mcp/vendor/pi-mcp-adapter.mjs`（ESM + createRequire banner），主进程直接 import 这个 vendor 文件；代码变更后需 `pnpm build:mcp-adapter` 重新生成

## 4. 核心实现原理

### 4.1 Agent 会话链路（聊天主流程）

```
ChatInput.sendMessage(text, attachments, taskReferences)
  → appStore.sendMessage          # 首条消息时 materialize 任务（新建任务草稿态）
  → window.api.agent.prompt({taskId, text, modelId, thinkingLevel,
                             permissionMode, welcomeMode, spaceId, cwd, attachments})
  → AgentService.prompt
      ├─ await memoryWriteQueue    # 等上一轮记忆抽取写完，避免并发写 jsonl
      ├─ SessionRegistry 取/建会话：
      │    · 已有会话且 cwd/spaceId 变了 → 重建
      │    · 记忆失效标记(stale)且空闲 → 重建（记忆变更后下一轮生效）
      │    · 专家目标变了且空闲 → applyExpertToSession 热替换（改 loader.appendSystemPromptSource + session.reload()）
      │    · 都没有 → createSession
      ├─ setModel / setThinkingLevel
      ├─ 发 assistant_start 补丁
      ├─ session.prompt(text)      # pi 内部跑完整 Agent 循环（工具调用/思考/流式）
      └─ 结束后：产物 diff（snapshotWorkspace 前后对比）→ 上下文用量落库 → 排入记忆抽取队列
  ← session.subscribe 事件 → mapPiEventToPatches → AgentUiPatch
  ← broadcast("agent:event") → preload → appStore.applyAgentPatch → 聊天 UI 流式渲染
```

**createSession 的装配细节**（理解 Agent 能力的关键）：

1. `DefaultResourceLoader` 用 `appendSystemPrompt` 注入 `assemblePrompt()` 拼出的全部系统提示段
2. 扩展工厂按序注入：**MCP inline 扩展（按场景过滤）→ 权限扩展 → 文件备份扩展**（备份必须在权限之后：审批通过才留备份）
3. `createAgentSession` 传 `tools: resolveSessionTools(...)`——readonly 模式只给 `read/grep/find/ls`
4. `await session.bindExtensions({ uiContext, mode: "rpc" })`——**必须显式调用**，pi 的 createAgentSession 不会自动 bind；这一步才触发扩展 `session_start`（pi-mcp-adapter 在此初始化）
5. `session.subscribe` 订阅全部事件，映射为 UI 补丁

### 4.2 系统提示装配（PromptAssembly）

`assemblePrompt()` 是**唯一** system 拼装入口，`createSession` 与设置页"装配预览"共用，返回带 `segments[]` 追踪的 `AssemblyTraceDto`：

| 段 | 来源 | 内容 |
|---|---|---|
| soul | db | 人设（名称/称呼/性格） |
| mode | seed⊕user | 场景模式五块（目标/工作流程/交付要求/禁止事项/验收标准）+ 工具偏好 + MCP 场景策略 |
| expert | 专家目录 | 「## 专家角色」正文 |
| skillCatalog | 技能目录 | 按场景过滤后的技能列表（enable 才列出） |
| shell | runtime | Windows Shell 提示（pwsh 或 Git Bash 说明，跟随 pi 的 shellPath 配置） |
| memoryRules | runtime | 长期记忆开关规则（开/关两种文案） |
| globalMemory / spaceMemory | db | 全局摘要（40 条）+ 当前空间记忆（自动+手动） |
| permission | runtime | 当前权限模式声明 |

附带回显：`totalChars` 超 1.2 万字符告警、空块告警、硬策略告警。`resolveSessionTools` 实现 readonly 收窄与 hard deny 剔除。

### 4.3 事件流与 UI 补丁（双缓冲节流）

- 主进程侧：`emitPatch` 把连续同类 `text_delta` **合并**后缓存，16ms 定时 flush——避免每 token 一次 IPC
- 渲染层侧：`initRuntime` 订阅 `agent:event`，delta 进队列按 **requestAnimationFrame + 40ms 兜底定时器**（窗口后台时 RAF 被节流，定时器保证流式持续推进）批量 `applyAgentDeltaBatch`
- 结构性事件（tool_start/artifact/assistant_end…）必须排在此前文本之后：两层都会先 flush 待发送 delta 再发结构事件，保证顺序
- StrictMode/HMR 防重：模块级 `agentEventUnsub` 单例，重复订阅先卸旧

补丁类型（renderer 唯一增量来源）：`assistant_start / text_delta / thinking_delta / tool_start(pending_approval|running) / tool_update / artifact / assistant_end / context_usage`。

### 4.4 权限与审批（permission-extension）

三档权限由**双保险**实现：

| 模式 | 扩展行为 | 工具列表 |
|---|---|---|
| default | 危险工具（write/edit/bash rm 等）发 `tool_start(pending_approval)`，Promise 挂进 `entry.pendingApprovals`，等 renderer 审批 | 全工具 |
| readonly | 请求直接拒绝 | `read/grep/find/ls` |
| auto | 一律放行（审批表也会被清空放行） | 全工具 |

`SessionRegistry.resolveApproval` 用 `toolCallId → resolve(approved)` 的 Map 完成异步桥接；`setPermissionMode` 切 auto 时自动放行所有挂起工具并回发 running 补丁。登录态全局 `permissionMode` 存在 settings.json，会话级可即时切换。

### 4.5 会话持久化与重新生成

- **会话文件**：pi 的 `SessionManager` 把会话写为 jsonl（`~/.mybuddy/sessions/<编码cwd>/`），SQLite 只存 `session_file` 索引；重启后 `SessionManager.open(sessionFile)` 恢复同一会话，UI 历史经 `loadTaskHistory` 从 jsonl 解析回放
- **重新生成**：`session.getUserMessagesForForking()` 找目标用户消息 → `session.navigateTree(entryId)` 把叶子指针移回分支点（旧分支留在 jsonl 但不进上下文）→ 复用 `prompt()` 全链路
- **上下文用量**：`session.getContextUsage()` 在 message/turn/tool/compaction/agent 边界刷新，`context_usage` 补丁推 UI，同时落库 `tasks.context_*` 快照——重启后 registry 为空也能显示上次用量

### 4.6 长期记忆（MemoryService）

每轮 prompt 结束后**异步**排入串行队列 `memoryWriteQueue`（新 prompt 必须 `await` 它，避免并发写库/会话）：

1. 调用 `modelRuntime.completeSimple`（maxTokens 700、temperature 0、无缓存）跑专用抽取提示词，输入 = 现有记忆 + 本轮对话（截断：用户 12k / 助手 10k 字符）
2. 解析 JSON 输出（容错：code fence / 裸 JSON 截取），**严格清洗**：去列表符号、压空白、500 字符上限、敏感词/API key/40+ hex 正则过滤、规范化去重
3. 应用 `replaces`/`deletes`：模糊匹配（NFKC 归一化后精确/包含两种回退），新增记忆插到队首
4. 容量：全局 digest 40 条；空间记忆自动来源 80 条封顶（旧的自动条目裁剪，手动不动）
5. 变更后：标记相关会话 stale → 下一轮 prompt 自动重建会话（让新记忆生效），并广播 `db:memoryChanged` 实时刷新设置页

### 4.7 专家

**存储布局**（对齐 CodeBuddy/官方插件生态）：

```text
~/.mybuddy/experts/<slug>/
  ├── expert.json      # 元信息 / enabled / source / skills
  ├── prompt.md        # 角色 Prompt
  ├── skills/          # 可选 Private Skills
  └── avatar.*         # 可选头像
```

- **市场**：只暴露单专家；内置专家 + 本地市场/参考归档中的 `expertType=agent` 包。参考归档即使含 Team 包，也不会进入产品市场列表。
- **安装/导入**：支持官方 `.codebuddy-plugin` 目录与 ZIP；`expertType=team` 在直接导入时明确拒绝，避免把团长/成员误装成普通专家。
- **Private Skills**：专家包自带 skills 进入当前专家的候选能力集，但仍受统一 Mode / Project / Tag Skill Policy 过滤，不污染 Global Skill Center。
- **召唤注入**：`createSession` 时把专家角色 Prompt、Private Skills 与 Connector / MCP / Permission / Memory 等一起走统一 Runtime Assembly；任务中途切换专家会让下一轮按统一装配链重建。
- **旧数据**：旧 `kind=team` / `teamOf` 安装记录不再暴露；旧任务 `team:*` 选择降级为无专家。不存在独立 Team runtime / `teamPrompt`。

### 4.8 HTML 产物预览（ArtifactPreviewHost）

这是最有技术含量的部分之一：

- **为什么不用 iframe**：受限 iframe 无法完整渲染复杂 HTML/JS 产物，改用 Electron 原生 **WebContentsView**（完整 Chromium 渲染）
- **隔离**：独立 webContents，`sandbox: true + contextIsolation + 无 nodeIntegration + 无 preload`——不可信产物页面完全隔离；新窗口一律 deny，外部导航走系统浏览器
- **内容投递**：自定义协议 `mybuddy-artifact://local/{encodeURIComponent(id)}/`，在 `app.whenReady` 前注册特权（standard/secure/supportFetchAPI/corsEnabled）；host 固定 ASCII `local`（Chromium 对非 ASCII host 做 IDN 转换，不能承载 id）
- **磁盘产物**：有 `filePath` 时从磁盘读，相对资源按产物同目录解析，**防路径逃逸**（resolve 后必须仍在 base 内，否则 403）
- **纯内存产物**（画布等）：renderer 注册的 content 字符串兜底
- **导航竞态**：`navigationGeneration` 计数 + ERR_ABORTED 过滤——React StrictMode 双执行、快速切换产物、关闭面板都会合法中断上一轮 loadURL，不算错误
- **区域同步**：renderer 把宿主矩形（DIP）经 `artifact:setRect` 上报，主进程 setBounds；面板消失/页面切换时 App 统一 `artifact:close`

### 4.9 MCP 集成（配置 + 运行时双层）

**配置层（McpConfigService）**：发现全部来源（通用全局 `~/.config/mcp/.agents` + 应用全局 `~/.mybuddy/mcp.json` + cursor/claude-code/codex 等兼容来源，自包含 JSONC/TOML 解析），安装 = 复制进应用全局，启停 = `enabled` 字段。

**运行时层（McpRuntimeService）**：

- 每个 Agent 会话创建时，把 adapter 的 inline 扩展注入 `DefaultResourceLoader.extensionFactories`（经 `McpModeFilter` 按场景过滤——serena/codegraph 默认仅 coding 会话加载），并用共享 `EventBusController` 接收 `MCP_STATUS_EVENT`
- `bindExtensions({uiContext, mode:"rpc"})` 把 UI 桥注入：adapter 的 OAuth/sampling 交互经 `mcp:uiPrompt` 走到前端弹窗
- OAuth：动态客户端注册 + 本地回调 + **OS keyring**（@napi-rs/keyring，asarUnpack）+ 浏览器授权 + 手动 redirectUrl 兜底
- 无头会话：无对话任务时的 MCP 运行时容器
- `PI_CODING_AGENT_DIR=~/.mybuddy` 使 adapter 的缓存/配置落位应用目录

### 4.10 工作区与产物索引

- `listWorkspaceFiles`：递归扫描（深度 12 / 5000 文件上限），忽略 `.git/node_modules/.venv/out/release` 等；`readWorkspaceFile` 有 `assertInsideRoot` 防目录逃逸
- `previewWorkspaceFile`：文本直读；docx/xlsx/pptx 用 JSZip 解包 XML 抽取文本渲染成预览 HTML（带明暗色适配）；pdf/图片转 base64 data URL
- `snapshotWorkspace`：`size:mtimeMs` 签名快照，prompt 前后对比出"本轮变更文件"清单
- 产物索引：write/edit 成功后 `rememberTaskArtifact` 写 `~/.mybuddy/artifact-index.json`，供"我的文件"页按空间分组定位

### 4.11 自动化（CronService）

- croner 调度，支持 `at`（一次性定时）/ `every`（`N[s|m|h|d]` 转 cron）/ `cron` 表达式，默认时区 Asia/Shanghai
- 到点 `execute`：落库 cron_runs(running) → `agent.prompt({permissionMode:"auto", welcomeMode:"working", taskId:"cron-…"})` → 更新 run 状态 + 广播事件
- 启停/删除即时 disarm 定时器；重启从库恢复所有 enabled 任务

### 4.12 IM 网关（GatewayService）

- 本机 HTTP 服务 `127.0.0.1:52140`，路由 `/feishu|/wecom|/wechat`（webhook 回调），Telegram 走长轮询（无需公网，推荐）
- **幂等去重**：`channelId:chatId:messageId` 10 分钟窗口（先清过期再查重，修复过"过期后同键永远被拒"的 bug）
- **每通道白名单** `allowUsers`（空 = 不限制）
- secret 脱敏：`getChannelConfig` 打码（`••••••`），connect 提交占位符自动复用旧值
- 消息全部落库 `gateway_messages`（保留最近 3000 条），AssistantPage 按会话分组回放
- 重启自动 `restoreChannels()` 重连
- 微信/企微 AES-256-CBC 加解密 + 签名校验（wx-crypt.ts）

### 4.13 场景模式（welcomeMode）

`working | coding | design` 三模式：seed 文案（mode-defaults.ts）⊕ `~/.mybuddy/modes/<mode>/` 用户覆盖（可编辑的 md 块 + policy.json），策略分三层：**技能过滤**（prefer/demote/hide/allow）、**工具策略**（hard deny 真正从工具列表剔除）、**MCP 策略**（hard 时不注入 adapter）。设置页可逐块编辑/重置/整档重置，并实时 `assembleModePreview` 检视装配结果。

### 4.14 数据持久化（AppDatabase）

- better-sqlite3 同步 API（主进程单写者，无并发问题），WAL 模式
- 8 张表：`spaces / tasks / memories / soul / cron_jobs / cron_runs / gateway_channels / gateway_messages`
- **迁移策略**：`CREATE TABLE IF NOT EXISTS` + `pragma table_info` 探测列缺省 ALTER 补齐（archived/expert_id/context_* 等均幂等）
- 兜底约束：`spaces(name) COLLATE NOCASE` 唯一索引（失败仅告警不阻断）；upsertTask 自动占位创建空间（外键修复）
- 会话内容**不在** SQLite：jsonl 是唯一真相，库只做索引/元数据

### 4.15 渲染层（Zustand 单 store）

- `appStore.ts` 单 store 全量状态（页面/任务/空间/技能/专家/MCP/面板/草稿…），`initRuntime` 用 `Promise.all` 并行首屏加载 11 组数据
- **新任务草稿态**：点「新建任务」只登记 `draft`（spaceId/expertId），切走即丢；`sendMessage` 首条消息才 materialize 落库——杜绝空白任务行
- **引用上下文注入**：选中历史消息后，用 `<!-- mybuddy:reference-context -->` 隐藏块拼进 prompt 文本，主进程不感知（纯 prompt 层）
- 主题：CSS 变量 + `nativeTheme` 同步，`theme:request`/`theme:set` 双向同步原生标题栏（titleBarOverlay 32px）
- 右栏四视图：文件 / 概览（产物流）/ 工作空间（文件树）/ 变更；悬浮层（flyout）与原生 WCV 交互有专门的状态机（pin、菜单打开时隐藏 WCV 等）

## 6. 运行方式

### 6.1 环境要求

- Windows（当前开发机）/ macOS / Linux（代码有平台分支但主测 Windows）。Omarchy（Arch + Hyprland）本机跑法见 `docs/omarchy-linux.md`。
- Node ≥ 24（当前 v24.15.0）、pnpm ≥ 11
- `.npmrc` 已配 npmmirror 镜像（registry + electron 二进制镜像）
- 首次安装：`pnpm install`（better-sqlite3 / @napi-rs/keyring 需 native build，`pnpm-workspace.yaml` 的 `allowBuilds` 已放行；必要时 `pnpm exec electron-rebuild`）

### 6.2 开发

```bash
pnpm dev          # electron-vite dev：主进程/preload/renderer 三端 HMR，Electron 自动拉起
pnpm typecheck    # tsc --noEmit × 2（tsconfig.web.json + tsconfig.node.json）
pnpm build        # 构建到 out/（main/preload/renderer）
pnpm start        # electron-vite preview：预览构建产物
```

**使用前置条件**：`~/.mybuddy/models.json`（providers 配置）+ `~/.mybuddy/auth.json`（凭证）——没有则无模型可聊；也可在应用内 设置→模型 页面配置，或 设置→账号 走 `/login` 等价流程（API key 或 OAuth，凭证写 auth.json）。

### 6.3 打包

```bash
pnpm pack         # electron-vite build + electron-builder --dir（未打包目录）
pnpm dist         # electron-vite build + electron-builder --win（NSIS 安装包 → release/）
```

打包配置：appId `com.mybuddy.app`、productName MyBuddy、asarUnpack better-sqlite3 与 keyring 原生模块。**注意**：`dist` 尚未实跑验收过（STATUS.md 标注未验证）。

## 7. 安全设计要点

| 面 | 措施 |
|---|---|
| 不可信产物页面 | sandbox WCV + 无 preload/Node + 新窗口 deny + 外部导航转系统浏览器 |
| 产物协议 | 路径逃逸 403（resolve 后必须仍在产物目录内） |
| 工作区文件 | `assertInsideRoot` 防目录穿越 |
| Agent 权限 | default 危险工具审批 / readonly 工具白名单 / auto 显式放行；写操作先备份 |
| 记忆清洗 | API key/密码/令牌正则过滤 + 敏感词 + 规范化去重后才落库 |
| 凭证 | OAuth token 存 OS keyring（@napi-rs/keyring）；auth.json 仅 API key 类 |
| Gateway | 每通道 allowUsers 白名单 + 幂等去重 + secret 脱敏回填 |
| renderer | contextIsolation + 无 nodeIntegration，页面只能碰 preload 白名单 API |
