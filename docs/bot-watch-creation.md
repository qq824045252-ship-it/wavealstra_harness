# Bot 持续跟踪入口

## 用户可用操作

- 定期检查：`work_create` 使用 `mode: "watch"`，`watchRule.cronExpression` 与 IANA `timezone`。宿主持久保存订阅，默认等首次约定时间；用户要求现在也检查时才 `startImmediately: true`。
- 一次性跟进：`watchRule.nextWakeAt` 是 Unix 毫秒时间戳。首次触发后没有后续时间，不会自行重复。
- 到期检查：`deadlineAt` 独立于 Bot 授权期限，到期只读整理成果与缺口，不等同于取消。
- 调整：先查 `work_query_status`，再用同一请求读到的完整 `versionGuard` 调 `work_amend`。只改时间表不生成新的业务输入、不使已有成果失效、不立即重跑原任务。
- 团队委托暂不支持附加定时/期限检查，入口明确拒绝并提示新建独立只读关注事项，不会成功接收后静默丢触发。
- 只停止后续检查：`work_amend` 的 `watchRule: null`，保留原事项及成果；暂停、恢复、取消整个事项复用现有控制工具。

不确定检查时间或频率时前台澄清这一项，不擅自承诺高频轮询。前台定期规则使用五字段分钟级 Cron，不接受秒级轮询。时区默认使用实际宿主时区，用户指定优先。工具成功回执才表示已安排。详情页直接展示当前订阅的下次检查，不使用创建时过期的 nextWakeAt。

## 运行语义

复用 `WorkWatchScheduler` 和现有 inbox/outbox/dispatch queue。定时事件具有订阅、规则版本、逻辑时间槽身份。定时跟进取得独立只读执行，不因原事项输入相同而被误去重，也不改变原始委托输入以伪造新业务要求。

跟进及其恢复执行在原生任务权限和每个动作准入两层只允许 `workspace:read`（负责人身份不豁免），携带本次调度事实、原始要求、停止条件文字与最近报告摘要；不得重跑原委托的文件修改、付款或外部发送。完成本次检查后交回宿主，不由模型自行 sleep/循环。停止条件作为检查依据保留并汇报，不能把单次检查说成整个事项已验收。

- `latest`：离线仅定位最近一个已到期槽；慢消费者的未冻结、未派发旧 tick 被新槽取代，旧槽保留审计。
- `each`：每轮最多64槽且受当前订阅队列容量限制，容量不足保留持久游标等待后续扫描。
- `skip`：跳过过时槽，容许一个实际调度间隔的正常延迟。
- 暂停不派发；恢复按原策略处理遗漏。规则或补查策略变更后从当前重新排期，旧 pending tick 与尚未提交的旧派发不会误执行；停止后也一样。已经提交的原生回执仍只做恢复核对，保留已有成果。
- 退出、断网、休眠不等于持续在线。应用再次运行才恢复调度。cron 缺口只证明调度槽被恢复，不证明业务来源在离线期间没有变化。

## 验证入口

- `pnpm -s test:bot-watch-creation`：真实前台工具、SQLite 重开、派发队列、规则更新、只读重复检查、暂停/恢复、停止、一次性与到期去重。仅 native 模型执行使用适配器夹具。
- `pnpm -s test:bot-watch-scheduler`：多年离线、latest/each/skip、有界队列、冻结/已绑定保护、真实 host session、时区与 DST。
- `pnpm -s test:bot-watch:live`：隔离 HOME 的 `pnpm dev`、真实 Electron UI、真实模型、进程重启、到点执行。默认模型代理为 `127.0.0.1:3425/v1`；可用 `BOT_FRONTDOOR_BASE_URL` 和 `BOT_FRONTDOOR_MODEL` 指定已验证代理。没有代理或桌面环境应失败，不得称通过。

不打包、不改真实用户配置、不提升权限、不恢复预算或审批界面。headless renderer 运行只能证明渲染和 IPC，不能声称 Omarchy 桌面输入通过。
