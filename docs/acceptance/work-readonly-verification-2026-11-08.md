# Work read-only verification follow-up

Baseline: `cb10b10a961d1dce227baf94dcdb7e1d477f7bef`.

## Changes

- A complete literal-only bash grammar now recognizes one explicitly named target for `ls -l/-1/-A` (combined listing flags accepted), `wc -c/-l`, `stat`, `sha256sum`, `sha1sum`, `md5sum`, `du -b` and `od -c`. Bare `pwd`, `ls` and existing single-path `cat`/`ls` retain their host-file adapters.
- Linux verification runs the real fixed system utility with argv, not shell text. PATH, shell startup files, exported shell functions and user environment are not inherited. The checked open file descriptor is inherited as FD 3; the command receives `/proc/self/fd/3`. Original stdout is retained. The result identifies the real executable/argv and the descriptor's requested workspace target. This is actual command evidence, not a model-calculated byte count or a forged claim to have executed the user's raw shell string.
- Both pre-resource admission and execution validate lexical and canonical workspace containment. Verification uses a conservative host-wide read lease, excluding managed writers without any pathname content hashing in the resource gate; the executor alone opens and checks the pinned descriptor. Devices, sockets, FIFOs and multiply linked regular files are refused. Execution checks the opened inode and descriptor target before launching the utility, and detects target size/time changes before accepting the result. `ls` does not recursively follow child links; `-a` is not allowed because long listings of `..` could expose parent metadata (`-A` is available instead). `du -b` only accepts a file; recursive directory scans are not added.
- Unsupported flags, multiple targets, substitutions, redirects, pipelines, arbitrary awk programs and alternate shell tools remain outside this allowance. Windows/macOS have no new system-command backend in this change and explicitly report that limitation rather than simulate a successful command. The old `read` fallback remains available.
- Count/hash/stat/list evidence does not become a content-read baseline authorizing later overwrite. Existing opaque observations and unknown-effect barriers remain intact. No scope is expanded or Work automatically accepted.
- The real-environment form has an explicit “带入要求环境” button. It copies only the selected requirement text after a user click; it does not create test evidence or submit a pass. Additional system details remain in the verification description.
- Closure displays the precise disabled reason beside its button. A stale snapshot has a nearby latest-state review action, which still clears the old closure confirmation and requires a fresh confirmation. Drafts and uncertain-request identity remain protected.
