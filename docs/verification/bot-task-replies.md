# 原回复内任务阶段：开发态验收地图

同一 Bot 对话里的独立任务，各自留在创建它的助手回复中。阶段 Tab 负责阅读该任务的任务说明、执行记录、核对和结果。发送仍走原来的底部输入框；后台回流不应替读者切 Tab、丢草稿或拉走阅读位置。

## 入口与范围

```sh
pnpm -s test:bot-task-reply-harness
pnpm -s test:bot-task-reply:dev
```

第一条验证本地 TCP 上的模型协议、CDP 驱动和失败报告，不启动 Electron。它按仓库分类列入 NETWORK，**只监听 `127.0.0.1`，不访问外网**。第二条启动隔离的 `pnpm dev`，操作真实 Electron 的 Bot 页面、preload、主进程 IPC、原生执行与 SQLite，再重载渲染器和重启主进程。

第二条需要可用桌面会话、仓库要求的 Node/pnpm、安装完整的 Electron 与原生依赖。Linux 缺少 `DISPLAY`/`WAYLAND_DISPLAY` 时立即失败，不自动转成 headless、虚拟 DOM 或跳过成功。仅设置变量也不会通过：连接不到本次启动的主进程、渲染器或应用入口时仍失败。已有用户实例不会被附着或关闭。验收不执行 `pnpm build`、打包或安装。

`pnpm dev` 自身会生成运行所需的开发输出，位于本次诊断目录的 `launch-N/dev-output`；这不是发行包验收。

### 固定数据与模型边界

每次生成独立临时用户目录和两个任务标记。重现同一组内容可设置 `BOT_TASK_REPLY_SEED=reply-demo`，允许 1–40 位英文字母、数字、下划线或连字符。运行目录仍唯一，重复运行不会复用旧数据库。

默认 `BOT_TASK_REPLY_MODEL_MODE=fixture`：唯一替换的业务边界是本地 OpenAI 兼容 HTTP 模型服务。前台真实工具调用创建 Work；后台真实执行返回文本；真实结果核对回合收到匹配的已交付成果后，夹具才返回结构化完成判断。夹具分别暂缓 A/B 的执行响应和核对响应，让测试在确定的时点操作 UI。它不改 SQLite、不改 `window.api`、不写应用 store、不把后台结果直接塞进渲染器。

这能验证应用集成与持久化，**不证明真实模型的推理、工具选择或完成判断质量**。

需要另跑真实模型时，显式设置：

| 变量 | 要求 |
| --- | --- |
| `BOT_TASK_REPLY_MODEL_MODE` | `live` |
| `BOT_TASK_REPLY_LIVE_BASE_URL` | OpenAI 兼容接口的基础 URL，例如本机已有模型网关的 `/v1` |
| `BOT_TASK_REPLY_LIVE_MODEL` | 该接口中实际可用的模型 ID |
| `BOT_TASK_REPLY_LIVE_API_KEY` | 仅在该接口要求时提供 |

live 模式转发实际模型请求/响应，保留相同的传输暂缓点与验收断言，不生成替代答案。缺配置、真实模型没完成预期委托或响应不符合生产契约时失败，不降级为 fixture。凭据仅由本地代理用于上游请求，不写证据文件、不传给被测应用，也不从现有用户配置、dotenv 或认证文件读取。live 模式会产生所配置服务的实际模型调用。

## 功能地图

### 1. 创建和并行处理（`02-dispatch`）

**子行为：** 独立任务 A/B、后台执行中的前台快答、原回复归属。

**用户入口：** 账户菜单 → Bot 模式 → 底部原输入框 → 发送。

**驱动与可观测结果：**

- 从空的隔离配置启动；通过真实菜单打开 Bot 页面，核对宿主具有 authority。
- 发送 A，直到本地代理观察到其后台原生模型请求；暂缓 A 的响应。
- 发送 B，再发送一条只需前台直接回答的问题。B 的创建回复和快答应完成，Work 总数仍为 2。
- 通过真实 IPC 读取发送回执对应的 `requestId`、`conversationId`、`workId` 与助手 `messageId`。每个 Work 只出现一张阶段卡，且位于对应的原助手回复内。

**注意：** 两张卡的归属来自持久身份，不根据标题或相邻位置推断。这里验证前台可在后台任务执行时继续处理请求；不把“第二个 Work 已排队”声称为两个原生执行器同时占用执行资源。

### 2. 阶段切换与草稿（`03-tabs-draft`）

**子行为：** 任务间独立选择、键盘切换、唯一输入框、真实阅读位置。

**用户入口：** 原助手回复内的任务 / 执行 / 核对 / 结果 Tab，以及原底部输入框。

**驱动与可观测结果：**

- 对 A 选择任务，对 B 选择核对；在 A 上按方向右键，只有 A 改为执行。
- 检查每个 Tab 的 `aria-controls`/`aria-labelledby` 对应同一任务内部面板。
- 写入尚未发送的草稿，用真实 CDP 滚轮离开底部。记录输入焦点、滚动位置、原回复和输入框的真实 DOM 引用。
- 页面始终只有一个原输入框，输入框不进入任何任务阶段卡。

**注意：** CDP 鼠标与键盘事件驱动真实 Chromium 控件；这里不验证操作系统原生输入、Wayland 焦点或 AT-SPI。阶段选择是阅读状态，不要求在整个应用重启后保留；重启后的业务归属和内容另行检查。

### 3. 后台回流与核对（`04-background-review`）

**子行为：** 后台进度回到原回复、读者状态不被抢走、原生执行结果可读回。

**用户入口：** 保持 A 的任务 Tab 和 B 的核对 Tab，等待后台回流。

**驱动与可观测结果：**

- 释放 A 的模型执行响应；直到生产链路保存原生执行完成，并实际发起结果核对模型请求。
- 暂缓核对响应，检查原回复、A/B 卡片和输入框节点仍是原节点；草稿、选中阶段和焦点保持。
- 滚动位置变化不超过 2 CSS 像素，外层助手回复 ID 列表不增长。

**注意：** “执行器完成”不是任务成功；测试继续等待实际结果核对、关闭与原会话投递，不用执行器状态直接断言整项任务完成。

### 4. 结果和持久事实（`05-reviewed-results`）

**子行为：** 自动完成、A/B 成果分开、同任务反馈去重、UI 与 SQLite 一致。

**用户入口：** 各自原回复内的结果 Tab。

**驱动与可观测结果：**

- 依次释放 A 核对、B 执行和 B 核对响应；等待两个 Work 由生产结果处理逻辑关闭。
- 结果 Tab 中能看到自己的专属标记，不能出现另一任务标记。后台回流不新增外层助手回复，不清空草稿。
- 以只读连接检查真实 `app.db`：两条 Work、两条执行绑定、原助手回复的精确会话/请求/Work 关联及持久反馈记录。已关闭的结论必须为成功；夹具异常不能被当作成功。

**注意：** 本场景是文本交付，未覆盖真实文件预览、下载、外部渠道发送或额外审批；相应功能应使用各自现有验收入口。

### 5. 恢复和会话边界（`06-renderer-reload`—`08-new-conversation`）

**子行为：** 渲染器重载、主进程重启、原记录恢复、新对话隔离。

**用户入口：** 应用重新打开后的原 Bot 对话；新对话按钮 → 现有“归档并开始新对话”操作。

**驱动与可观测结果：**

- 先重载渲染器，再只停止本次启动的 Electron 主进程；用同一隔离用户目录再次启动 `pnpm dev`。
- 核对主进程 PID 确实改变；重读后卡片仍属于原助手回复，两个结果可打开，SQLite 中的消息、反馈、Work 与执行绑定不被重写或重复创建。
- fixture 模式中，每个任务的原生执行 HTTP 请求仍只有一次，已完成任务没有因重启而再次执行。
- 通过现有新对话入口建立新会话，新会话不显示旧任务卡；旧消息和任务仍保留原有持久身份。

**注意：** 这验证已完成任务的持久恢复，不覆盖工具执行中断电、未知外部效果、跨设备重连或历史分页。这些不能从本报告推断为通过。

## 证据与失败处理

每次运行保留 `out/diagnostics/bot-task-replies/<时间>-<seed>/`：

- `report.json`：完整步骤、实际请求/会话/Work/回复身份、fixture/live 标识、失败原因与明确限制。
- 每步截图与 accessibility 树；失败且仍能连接时另保存失败画面。
- `provider-requests.json`：临时场景的实际模型请求、阶段、上游状态及错误，不含授权请求头。
- `launch-N/dev.log`、真实主/渲染进程身份、Electron/Node/Chromium 版本、实际开发主进程/preload 文件摘要。
- 启动和结束时的源码指纹。验收中源文件改变则报告失败，不能把混合版本结果当作一次有效验收。
- 关闭前后只读取得的 SQLite 身份与结果快照。

隔离目录保留便于诊断；不读取用户现有 `~/.mybuddy`。进程清理由随机运行身份及唯一 bootstrap 限定，先让自己的主进程退出，再收束自己的 pnpm 启动进程组，不按进程名关闭用户应用。随机端口不是归属证明：主进程核对运行 token 与临时目录后，必须通过自己的 webContents 给渲染器写本次 nonce，CDP 连接先验证 nonce 才操作页面。

预检失败、启动失败、入口不可达、断言失败、模型/清理错误或源码变化均非零退出。缺桌面时仍保留失败报告，**不会产生 GUI PASS，也不会伪造截图**。`test:bot-task-reply-harness` 的成功只代表 TCP/驱动基础检查通过，不能代替 `test:bot-task-reply:dev`。
