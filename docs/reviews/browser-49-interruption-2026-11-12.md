## 新增可复现测试

依赖按仓库锁文件及补丁安装后运行：

```sh
node scripts/browser-durable-interruption-test.mjs
```

运行器将 fixture 打包为独立 Node 子进程。测试使用真实 `DurableBotRuntime`、Pi Codemode、持久 journal 和同一 `stable-input` 身份。模型流与 `browser_exec` 是明确的本地替身，不启动 Electron，不访问网络模型。

1. Codemode 依次调用四个已知步骤。前两步返回成功。
2. 第三步真实追加临时文件副作用，写入检查点，然后停在未返回回执的 handler 内。
3. 父进程确认检查点后，仅强杀自己创建的这个子进程。
4. 第二个进程打开相同持久状态、提交相同输入身份，读取原生恢复结果。
5. 断言原生嵌套记录为 `ok, ok, error`，包含 `interrupted and may have partially run`。外部效果账本严格为 `1,2,3` 各一次，恢复没有再次调用浏览器 handler，第四步没有发生。

合成模型只确认收到原生错误并结束测试。其 `done` 不表示第三步业务成功，也不表示真实模型已经能正确处置该错误。

最终断言运行通过。持久数据与 worker 日志保留在运行器打印的临时目录，日志只有合成参数和测试结果。此前两个诊断问题已排除：独立副本模块解析器未处理 exports 通配符；旧 fixture 错误地要求中断结果也必须成功。这两者是测试准备问题，不登记为产品缺陷。

### 验证边界

此测试验证真正的进程强杀、原生恢复身份与不重放性质，补上原测试仅在任务完成后关闭重开的缺口。临时文件是真实副作用，但浏览器端口为替身，因此不能声称实际网页提交、DOM 状态恢复、Electron 重启、真实模型质量或实机性能已经通过。
