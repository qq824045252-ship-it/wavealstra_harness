# Bot 团队按当前委托分工

## 交付范围

前台 `work_team_create` 新增可选 `taskAssignment`：Bot 查询已保存团队后，可为本次委托选择其中需要的成员，指定具体职责、成员顺序及前置依赖，最后由当前负责人汇总。省略参数仍复用原分工。模板查询提供成员真实名字和职责摘要，不要求模型猜测内部 ID。

这不是另一套执行器，不创建新 Bot、不修改成员资料，也不覆盖保存的模板。成员身份和各自 scope 由宿主从模板取得；负责人、执行策略、并发上限及工作目录沿用既有入口。不能通过参数增加成员、扩大权限、形成循环或引用未选成员。

追加自由组队：不再要求先保存模板。`work_team_templates` 同时返回当前工作目录可用的现有 Bot 名字、职责、范围；省略 `templateId`、提供 `taskAssignment` 即可直接选择成员并安排依赖，默认最多 2 个成员并行。宿主固定负责人，成员范围来自负责人和成员已有 workspace scope 的交集，检查当前真实用户消息与活跃回复回执；不伪造用户 actor，不创建 Bot 或权限记录，不覆盖模板。

“自由”指从当前用户已启用的 Bot 自主选人；没有相应现有访问范围、过期或其他用户的 Bot 不参与。自动创建新 Bot、执行途中自动重排仍不在本批范围。

## 验证

- `pnpm -s typecheck`：通过。
- `test:bot-work-team-access`：通过。包括旧模板创建、用户原文关联、重放不重复、实际职责改变、成员子集、按任务重排依赖、并发上限保留、模板未改变、无效成员/重复成员/自依赖/越权 scope 拒绝且无新增团队。
- `test:bot-work-team-service`：通过，复用现有团队派发和依赖服务。
- Omarchy `pnpm -s test:bot-frontdoor:live --team-planning`：隔离 HOME、真实 Electron 渲染页、真实 DeepSeek 模型。模板只保存通用职责；用户要求甲读取 beta、乙等甲完成后读取 alpha 并核对甲结果。模型生成实际职责和依赖，成员读取真实文件，负责人独立回读并返回原始 Bot 会话。一个 Work、三个团队执行，返回 ALPHA-31415 / BETA-27182；保存模板保持原样。
- `test:bot-work-foreground-contract`：通过（87 个无效输入、请求/事项/对话身份、目标解析、重放与终止请求检查）。
- 无模板行为回归覆盖：候选只来自同一用户、直接创建并保留真实源消息、成员权限取既有交集、没有保存模板、重放不重复、缺分工/伪造源消息/跨用户成员拒绝。
- Omarchy `pnpm -s test:bot-frontdoor:live --team-free`：真实模型从现有 Bot 直接创建团队并完成文件读取、依赖核对与负责人汇总；模板表保持 0，无重复普通 Work。
- GUI 是真实 Electron 页面交互/CDP 验收，不声称验证了操作系统原生输入驱动。

默认全量曾启动，发现其中包含强杀/崩溃注入串行套件后，遵从用户暂停该类测试的要求，在进入该池前终止；不能称为全量门禁通过。本次不执行崩溃注入，不验证未知效果恢复，不使用用户生产 profile。

## 可复验

`TMPDIR` 应指向有容量的测试目录，然后执行 `pnpm -s test:bot-frontdoor:live --team-planning`。记录与截图在 `out/diagnostics/bot-team-planning/live/`；这些是本机诊断产物，不提交模型调用记录或临时 profile。
