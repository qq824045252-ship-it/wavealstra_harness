# 首轮零缓存诊断误报修复

用户截图中首轮 `cacheRead=0` 被 C3 判为“需注意”，卡片文字和曲线也标红。原实现把“当前为零”误当成“由已命中降到零”；UI 又独立按零值着色。

修复：
- 每个诊断分组独立建立已命中历史。首个有效观测为 0 仅作基线，连续冷缓存不虚构“掉到零”。
- 首轮如果有预热缓存/跨请求缓存，仍如实保留命中率，不强制为零。
- 同组实际出现过正命中后归零，继续显示 C3；真实请求失败、工具失败等其他规则不豁免。
- 卡片和趋势点都采用 C3 结论着色，正常冷缓存不标红。真实 0 仍出现在统计和曲线上，未知值仍为未知。

验证：typecheck 通过；diagnostics-rules 72/0；task-diagnostics、bot-execution-diagnostics 通过；新增真实 Electron diagnostics-cache-ui 验证 0 → 90% → 0 的前两轮正常/第三轮需注意，以及子代理独立基线。离屏窗口截图已人工核对。新增GUI脚本明确分类，不进入默认无头套件。

本次纯诊断展示修复，按用户最新要求只跑相关专项，不重复全量门禁；未调用真实模型、未更改缓存策略或生产实例。
