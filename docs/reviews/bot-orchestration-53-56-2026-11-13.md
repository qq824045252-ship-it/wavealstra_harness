# Bot 编排与个人助理行为改进

本轮围绕完整需求交接、执行中调整方法、多事项控制和成果核对修改现有 Bot/Work 链路。基于本地 main 工作区实施，保留已有并行修改；未提交、推送、构建或打包。

## 用户可见的变化

| 场景 | 改进后的行为 | 主要入口 |
| --- | --- | --- |
| 用户先说明报价单格式，回答数量后说继续 | 前台可明确选择原要求、澄清问答及附件，作为本次 Work 的原文证据 | `sourceMessageIds`、`BotDelegationSources`、`BotConversationRepository` |
| 目标没变，数据源失败或需要调整分工 | 负责人修订同一 Work 的剩余计划，复用已完成成果 | `work_team_replan`、`WorkTeamService.replanFromResult` |
| main-only 下两个独立子任务 | 继承写工具不再把整个批次压成串行；实际工具按读写路径协调 | `DurableSubagents`、`DurableToolCoordination` |
| “暂停 A、恢复 B，C 照常” | 每个动作对应明确目标；成功项不会在另一项失败后重复执行 | `BotWorkTargetSelection`、`BotForegroundTools` |
| 成果存在缺项，续办方案被拒绝 | 将拒绝原因交回结果复核，允许有界修正；耗尽后如实交付已有成果和缺口 | `WorkCompletionCoordinator` |
| 主助理收到其他 Bot 的不完整答复 | 引用原要求与答复证据，交原 Bot 只读补查现有文件或来源 | `bot_collaborate(action=review_result)` |

## 需求与成果的身份

来源选择只接受本轮冻结且当前仍可见的消息，校验用户、会话、顺序、原文与附件身份。当前用户消息自动保留。用户原文、助理解释和其他 Bot 转述保留不同角色，后两者不能成为新的用户授权。完成复核、续办和 Watch 共用 `WorkRequestEvidence`，不再把整段对话都作为授权文本。

来源索引追加在本轮输入末尾。已有 native 历史保持原前缀，不因添加索引而重建成摘要。测试仍比较完整系统内容、工具声明和先前用户输入，仅排除 Pi 新会话生成且不会发送给 provider 的 system timestamp 元数据。

团队计划版本与用户目标版本分开。当前计划与明确继承的旧任务保存在现有 `plan_json`，幂等操作复用现有回执，无数据库 schema 升级。被剩余计划省略的已完成成果仍进入最终负责人交付；继承同时绑定 Watch 轮次，下一轮观察不会拿上一轮成果当作本轮完成。

修改或移除的旧执行继续保留身份。替代任务等待相关旧执行结算，独立任务可以继续启动。迟到的 prepare、结果与未知外部效果不能写入新任务或冒充新计划的成果。

## 并行与响应性

资源协调发生在实际工具执行处，恢复重放同样经过检查。已知文件读写按规范路径、目录包含关系和文件实体身份协调，覆盖硬链接和目录别名；未知 shell 或 MCP 写操作保守等待。模型声明的只读或路径不作为免锁依据。

前台查询、创建和控制 Work 属于宿主业务状态操作，不占文件锁。后台长操作不会阻塞新的委托、状态查询或取消。排队工具在真正执行前重新检查取消及当前要求；未启动的失败保存精确回执。已开始的工具在实际结束前继续持锁。

## 复核与反馈

续办方案中的缺项必须引用冻结用户原文。团队改计划还要引用本轮成果中的实际证据。宿主拒绝计划后，结果复核获得具体拒绝原因，同一证据下最多尝试三次。到达上限后先持久化部分交付决定，再走正常送达重试，不会因通知失败重跑业务。

协作补查只能沿当前回流与原协作进行，单协作最多两轮。宿主检查原用户摘录、答复引用、取消状态以及 Work 输入版本和负责人。接收 Bot 走自己的正常前台，但只开放读取能力；真实工具执行前再次检查，MCP 调用还需证明实际动作只读。补查不能创建、修改或重新派发 Work。

## 验证边界

这些行为测试调用真实宿主、SQLite 和原生运行时，模型决策由受控 provider 提供。尚未用真实联网模型评估是否能稳定选齐来源、合理拆分任务或主动补查，也未进行 GUI 或发行包验收。

宿主保证所选来源的身份、原文和可见性。哪些历史要求与当前目标有关、后续修改替换了哪些条款，仍需要模型结合原文判断；本轮没有新增逐条语义撤销解析器。

本轮没有把团队改成通用步骤图。同一 Bot 多阶段复用、按产物就绪启动下游、按文件类型自动安排验证，仍需后续场景驱动的设计。PDF 可打开、页面可交互、程序实际运行等要求已进入规划和复核约束，但没有新增统一的跨格式验证器。

文件协调仅覆盖本进程内工具执行期间；不覆盖外部进程、跨机器或工具返回后仍运行的后台副作用。无 Work 的协作补查只认可原始真实用户消息；尚未新增跨 Bot 的历史来源选择协议。多事项控制依赖明确动作与对象，歧义或未来条件不会被猜成即时操作。
