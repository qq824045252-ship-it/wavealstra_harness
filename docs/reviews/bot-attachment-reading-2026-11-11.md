# Bot small-document foreground reading

## Product scope

Reuse the existing Library extraction registry for small PDF, DOCX, XLSX and PPTX attachments. Simple questions and small calculations can be answered in the current Bot conversation instead of dispatching a Work solely because the input is an Office/PDF file. CSV/JSON retain their existing inline path. Immutable attachment snapshots and existing composer/UI are reused; there is no new inbox, permission flow, or model extraction call.

Files larger than 4 MiB, unsupported types, image-only documents, failed extraction or requests requiring complete layout/image verification retain the background path. Inline extracted document text has a shared 64,000-character limit. Truncation is explicitly shown to the model. The Library parser's eight-second budget is cooperative, **not a hard process timeout**.

## Accuracy fixes

- Preserve XLSX CSV quoting and empty columns instead of replacing all commas with spaces.
- Report the existing 5,000-row XLSX and 500-page PDF cutoffs as truncation, rather than pretending the complete document was read.
- Remind the model that text extraction does not verify images, layout or annotations.

## Verification

Isolated development clone and temporary HOME; production data and running production instance were not modified. Actual Electron renderer sends to `opendesign/deepseek-v4.1-flash-eco`, using generated real files (Office files generated by their corresponding libraries, not fake extensions).

Six distinct tasks passed: CSV inventory (17 + 29 = 46), JSON configuration (atlas/west-3/4), DOCX contract (Kappa/27 months/2030-04-16), XLSX expenses (73 + 126 = 199), PPTX project (Nova/June/Mira), PDF receipt (R672/USD83.50/cash). Each answer belonged to the correct request, used one model call, persisted an immutable attachment snapshot, and did not create a Work. Initial successful run elapsed 3.6–5.0 seconds per task. This is fixture evidence, not a universal latency guarantee.

Renderer screenshots at 1280 and 390 pixels were inspected; no horizontal overflow. The test seeds the selected file in the actual composer and clicks Send; **native OS file-picker interaction is not covered**. No claim of Office layout fidelity or OCR coverage.

Commands:

- `pnpm -s test:bot-attachments` (includes unreadable PDF, full Office fixtures, XLSX row cutoff and quoted/empty cells, 501-page PDF cutoff, long inline document truncation)

- Default headless suite excluding the 20 separately deferred recovery/fault-injection cases; the standard runner and failure baseline are not changed.

After rebasing on search quick-reply commit `243ea8e`: typecheck and attachment tests passed; six live tasks passed again (one model call each, about 3.5–4.5 seconds each); the same 413-case gate passed with 0 failures / 0 known failures / 0 regressions in 2.4 minutes.
