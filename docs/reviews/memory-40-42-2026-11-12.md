## 修改后的行为

### #40 只有明确遗忘指令才能撤销来源

`MemoryIntent.ts` 提供共享的操作判断。自动捕获、显式遗忘和写入证据检查采用同一结果。否定提醒、遗忘问句、命令实现讨论和引用不会授予删除权限。否定按子句生效，保留混合 forget-A/remember-B。

六种报告中的反例经过真实 `BotConversationMemory.capture()` 后，范围水位和定向失效表均为空，旧历史仍能返回。最短真实证据可以保存“不要忘记”支持的偏好。团队和共享渠道的提醒分别保存到团队与当前渠道会话，不能提升到私人或全局范围。

### #41 单条遗忘不再推进范围水位

`forget()` 和 `detachScope()` 在删除事务内写入 `memory_forget_targets`，记录范围、目标指纹、长度、截止时间和允许的新来源身份。指纹来自目标内容、修订和可分离的最短证据，不持久保存被忘内容明文。短 Latin 标识符按完整单词匹配，避免忘记 AI 时误伤 RainfallGauge。

历史引用和提炼对旧来源撤销相关证据子句。A 与 B 可以来自同条消息。撤销用户子句后，不能证明独立关系的原助手回答也撤销，保留的用户事实仍能支持 B。来源过滤发生在模型请求前，写入和候选审批时再检查；正在等待的旧提炼不能用过时资格写回 A，也不会整批丢掉合法 B。

只有明确整范围遗忘才推进 `memory_forget_watermarks`。同毫秒来源采用持久 ordinal，逆序完成不能把边界向前回退。无现成 L1 的明确遗忘仍留下目标约束，阻止迟到的旧来源。

新增表按当前 schema 幂等创建，没有升级 schema 或重建有效数据库。已有粗水位原样保留。本次没有足够信息判断旧水位中哪些属于误判，因此不会自动恢复此前屏蔽的历史。

定向匹配基于已知目标、修订和原话证据，不新增语义分类模型。不能分离的同一证据子句采用保守撤销；这不等于能识别任意无锚点的语义转述。

### #42 在完整合法范围内匹配后限量

`MemorySearchScope.ts` 统一范围、状态、种类和有效期 SQL 条件。FTS 直接联结完整合法范围；词法回退在 SQLite 内规范化并匹配整个范围，再按相关性展开有限候选。保留 NFKC、大小写和标点规范化。范围采用 `EXISTS`，重复绑定不能占用额外事实名额。没有把 1600/2000 等常量扩大后作为修复。

语义提供者沿用现有向量表和运行时，流式检查完整范围，只保留有界 top-k。进入 top-k 前检查实际可见性，返回后再查内容哈希、状态、有效期、范围和任务归属。迟到索引也必须核对当前记录，不能复活删除项。

无查询的稳定偏好选择保持原入口。词法回退仍有随范围增长的扫描与 SQLite 临时排序成本；语义端仍线性检查现有向量。本次没有承诺恒定耗时、恒定数据库临时空间或生产性能提升。

## 查询成本诊断

10K 合成数据的一次最终运行有五次前台查询，耗时为 45.55、39.01、46.97、44.44、41.18 ms。中位数约 44.44 ms，范围 39.01–46.97 ms。每次都确认唯一旧事实实际返回，五次总计展开 1200 个 DTO，未全量展开每次范围内的 10K 对象。五轮进程 RSS 增量约 51.9 MiB，未强制 GC，不能当作稳态内存、峰值或泄漏率。未隔离所有后台软件负载，这不是隔离性能基准，不报告提速倍数。

独立 CPU 诊断发现早期查询的主要成本在 SQLite 词法候选扫描。实际查询计划随后确认，`COALESCE(scope_id)` 使范围子查询只使用复合索引的 `scope_type` 前缀。改为真实范围列匹配后，FTS 和词法路径均使用 `idx_memory_scopes_lookup(scope_type, scope_id, memory_id)`，避免为每条记忆重复扫描整范围的绑定。最终词法计划仍包含合法范围规范化和临时排序。

原始诊断保存在 `out/tests/memory-issues-correctness.log`、`out/diagnostics/memory-issues-before-scope-index.log` 和 `out/diagnostics/memory-issues.cpuprofile`。性能数据只说明本组合成数据和本机运行成本。
