# 长对话历史读取与后台执行验收

实现与验收基于本地主线 `a43b4268`。本轮修改源码和测试，没有升级版本或生成产品构建。工作区原有的文档和图表改动保留。

## 历史页身份与提问定位

历史页原先携带短期只读 runtime 的随机 `epoch`。前端将它与任务实时快照的 `epoch` 比较，导致有效页无法加入窗口。现在 `historyId` 根据 SQLite 文件实例和分支生成，跨只读查看器和执行 runtime 保持一致；存储替换或分支变化会产生新身份。文件身份参与哈希，不把本地路径暴露给客户端。注入的测试存储按对象绑定身份。

实时增量传输仍使用独立随机 `epoch` 和递增 revision。桌面请求还检查任务、当前 runtime、窗口引用、游标和请求令牌，防止任务切换、重新生成、回到底部或后续定位后接收迟到页。远端历史分页同步使用 `historyId`。

提问查询从最近记录开始，每次最多处理 2,000 个 entries、返回 200 问，按旧到新返回本页，并给出 `nextBefore`。隐藏记录占满扫描预算时仍返回续页游标。菜单显示尚有更多内容，允许继续读取和重试，不把未读取部分当作空历史。

远距离跳转直接读取目标附近最多 50 个 entries，不再从最近窗口逐页寻找。定位窗口独立显示，支持向前读取和“加载较新消息”。没有把未读取的中间历史拼成连续对话。工具结果只回填已有工具行，不引入中间消息。回到底部或显式发送新消息恢复实时窗口。

真实 SDK 和 SQLite 夹具验证结果：

| 数据 | 提问续页 | 完整性和定位 |
| --- | --- | --- |
| 3,000 轮纯问答 | 15 页 | 3,000 问完整、无重复，第 1 问及第 2,500 问可直接读取 |
| 1,200 轮、24,000 个混合 entries | 12 页 | 1,200 问完整、无重复，第 1 问及第 1,100 问可直接读取 |

混合夹具每轮包含 18 条隐藏或工具 entries，验证 entries 与可见消息数量不同的情况。另覆盖独立只读 runtime、工具结果跨窗口回填、分支变化和只读存储不写入。

真实 React、Zustand 和 DOM 夹具覆盖续页、空可见页、重复点击、失败重试、独立 runtime 历史页接收、定位窗口、向后读取、回到底部、任务切换和 runtime 替换后的迟到响应。选择已显示的问题也会取消尚未返回的远距离定位请求。

## Watch 风险查询与团队准备

Watch 原先通过 `listBindings()` 读取全部历史绑定及每条绑定的 metrics。现在专用 SQL 只读取未结算绑定和操作需要的字段；操作查询联接来源绑定，以保留旧版本已失效执行中的未知外部效果。原有 lineage、完整风险指纹、展示上限及模型返回后的事实复查保留。

生产 `executionRisks()` 在真实 SQLite 上的查询计数断言如下。每种规模都实际读取并断言空风险结果，不包含数据生成阶段。

| 已完成历史绑定 | SQL 次数 | metrics 查询 |
| --- | --- | --- |
| 100 | 3 | 0 |
| 1,000 | 3 | 0 |
| 10,000 | 3 | 0 |

另验证旧版本未知写入仍列为风险，释放效果后风险集合和指纹随事实改变。这里没有测量整机延迟，不据查询次数推算提速百分比。

团队准备中的在途记录改按成员任务维护。并发名额计算准备中与未结束绑定的并集，同一成员不会重复占位。测试确认 A 准备挂起时无依赖的 B 能准备；20 次重复唤醒不重复派发；准备转为运行后仍占一席；结算释放名额后 C 才进入准备；取消后的迟到准备不能创建绑定。

完整 headless 门禁首轮还发现三处既有测试夹具问题：调度夹具缺少 `peers.origin`；QQ 测试仍断言不支持文件回传；Google Workspace 用同一 80ms 超时执行正常启动与挂起测试。三处均修改测试并通过针对性复跑，没有修改失败基线。自动完成测试在恢复原团队派发逻辑的生成脚本对照中也于同一断言失败，排除了本轮成员锁修改。

第二轮还暴露了 Phase 2 收条检查的时序敏感断言。该断言把整个消息 revision 不变等同于没有重复收条，现在直接检查收条 segments 原样保留、模型答复文本仍为空。没有放宽等待时间，也没有取消收条的数量或内容检查。

最终相关测试、桌面和远端 typecheck、测试分类审计及 `git diff --check` 均通过。第三轮完整 headless 门禁为 **523 通过、1 失败、已知失败基线 0**。失败项是本轮没有修改的 `test:memory-semantic-scale`，最后一次语义查询的事件循环延迟为 111.607807ms，超过原有 50ms 预算；查询耗时 1317.9376ms 仍在 1500ms 预算内，结果正确，RSS 预算也通过。前两轮该用例通过，此次超限尚未归因，不能据此称完整门禁通过。本轮没有调整该用例、性能预算或失败基线。

最终完整日志在 `out/tests/history-work-accepted-gate-20261113.log`。前两轮日志分别是 `out/tests/history-work-full-gate-20261113.log` 和 `out/tests/history-work-full-gate-final-20261113.log`。10K 用例仍实际持久化 10,000 个向量和 30,000 个范围绑定，没有更换小数据夹具。

本轮没有进行真实 Electron 界面的滚动和视觉验收，也没有运行真实模型或发行包。已有 dev 实例保留，没有停止用户正在使用的程序。
