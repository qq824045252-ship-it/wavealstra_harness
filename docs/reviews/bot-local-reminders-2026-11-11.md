# Bot 本机纯提醒闭环（2026-11-11）

## 范围

纯提醒复用现有 CronService 和自动化页面，不创建 Work，不启动后台模型。
Bot 用 `reminder_manage` 保存语义明确的提醒；相对秒数由宿主以收到本次用户消息的时间计算。到时 SQLite 事务落 Bot 消息、发送记录和下次游标，再由持久通知 outbox 投递已有通知服务。稳定 delivery ID 防止正常重启重复投递。

支持一次、间隔、每日/自定义 cron、时区、查询、改期、暂停/恢复、取消、稍后。稍后只修改下一次，不抹掉原重复周期。重复任务错过多轮时恢复仅补一条，并继续原周期。手动“立即运行”是标明的预览，不消费正式轮次。

个人提醒按 Bot 归属、跨新旧对话可管理；团队提醒按团队归属。消息回原对话；既有自动化页可查看/编辑。已提醒、已取消、已暂停分别展示。纯提醒编辑不显示无关模型/权限/技能等执行配置。

## 边界

这是**本机提醒**，不是云端推送服务。应用退出、电脑关机或休眠时不能承诺准时送达手机；再次打开合并迟到补发。系统弹窗仍遵守用户通知开关和系统支持情况。真实 UI 验收使用实际 Electron renderer + CDP headless；没有把它称为原生桌面鼠标或 OS 通知弹窗验收。

创建/更改时使用真实前台模型理解用户意图；到期发送完全不调用模型。需要到时检索、分析、操作外部服务的委托仍应使用 Work/watch，不伪装成纯提醒。

## 已有证据

- 首轮真实模型 `opendesign/deepseek-v4.1-flash-eco`、实际 Electron UI、隔离 HOME：7 类全通过。实际2分钟提醒从用户输入时刻计时，通知落库延迟9ms；到期新增模型调用0，Work新增0。
- 7 类：两分钟一次、重复与暂停、同一提醒改期、取消不误发、前台长回答期间到期、正常退出跨期重启补发、每日时区与稍后保留周期。
- 原生专项包含真实 SQLite/定时器、稳定操作去重、忙碌会话不阻塞、无模型/任务、正常重启游标、错过重复合并、预览不消费、暂停编辑恢复、标题编辑保留稍后时间、作用域、状态。
- 崩溃/故障注入依用户要求延后。非故障门禁用临时入口排除20项既有故障恢复测试；没有改正式 baseline 或把失败白名单化。
