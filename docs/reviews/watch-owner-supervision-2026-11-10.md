# 持续委托：每轮前台监督（2026-11-10）

## 范围与事实

定时轮次已有持久化，并不等于前台已在对照目标处理结果。本次添加独立 `WorkWatchSupervision`，每条持续委托按原始目标、本轮结果、最多前三轮观察进入真实 Bot 模型整理。它不抢占用户输入回合，同 Work 有序、跨 Work 两槽并发。结果按 execution binding 去重并回到原会话；模型结论先持久保存，投递失败只重试投递。模型失败有界重试后交付原始观察，不假称已核验。

每轮完成仍保持长期职责 active；暂停/closing 不承诺下一轮。只有宿主证实来源完整且无变化时可以静默，错误、不能比较的来源或模型整理失败不得伪装无变化。关闭事实独立回报，旧版本未报结果不被新监督通道吞掉。

## 真实验证

隔离 HOME、pnpm dev Electron、真实本机 DeepSeek V4.1 Flash 模型、真实文件 read、实际分钟时钟；未修改生产 profile，未做崩溃/强杀注入。

- `--watch-followup`：三轮 WAITING → READY → READY；每轮一条 `watch-supervision:` 回报，三轮均真实模型一次成功，Work 保持 active；用户暂停后实际等候 70 秒，无新执行。1280/390 宽度无横向溢出。
- `--watch-changes`：四轮通知数 0 / 0 / 1 / 0，途中正常退出/重启；原会话与基线保持，暂停后 70 秒无新执行。
- 首轮开发实测曾发现 once 结果协议的 `missing` 与 watch 返回值不匹配，触发原文回退；改为 watch 独立 outcome/reply 契约后重新完整实测通过，没有把回退当作模型成功。
- 专项回归：多轮/重复 wake/正常重建监督器/模型失败回退/投递失败不重复模型/上下文构造失败有界回退/关闭反馈可见。
- 类型检查、`test:work-conversation-feedback`、`test:work-watch-supervision`、`test:architecture-graph` 通过。未运行包含崩溃场景的全量门禁。

## 明确未覆盖

这不是“365 天不停占用一个模型进程”。宿主在线时按持久周期执行短轮次，离线不会真实抓取；恢复调度不代表补齐来源历史。没有实测 X 登录/API/分页历史，也没有泛化网页语义去重证明。

本提交监督回合核对目标、解释观察并继续已保存计划，不自主更改频率、不派发额外工具动作、不实现任意语义停止条件。明确时间期限由独立改动实现；团队创建的持续模式与自适应计划仍需后续完善。不能将此报告称为整个长期自治闭环全部完成。
