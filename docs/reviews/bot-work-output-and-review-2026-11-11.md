# Bot Work 输出配置与恢复审核竞态

## 原因与范围

复查 `bot-first-response-2026-11-11.md` 最终批次的隔离证据：155.365 秒结束的 Work 先遇到推理耗尽输出空间而空答，接续又两次截断。三次后台原生执行均失败。最后较完整的计划是结果整理回合重新组织出的文本，不能冒充成功的后台执行，因此原 `ended_unsuccessfully` 结论保留。

该批的 **4096 来自验收脚本** `bot-frontdoor-live-test.cjs` 写入隔离 profile 的模型定义，不是发现了产品 Work 的统一 4096 限制。脚本此前还按场景写死 16384，并把模型 reasoning 能力误设为仅在偏好测试时启用。

产品 Bot/Work 与结果审核沿所选模型目录执行，`DurableBotRuntime` 没有给这些请求覆盖 4096。当前 Pi `buildBaseOptions` 默认使用调用级 `maxTokens` 或 `model.maxTokens`，并按剩余上下文裁剪；其中 4096 是上下文安全余量，不能称作输出上限。模型定义和 override 可改变所选模型参数，不能拿另一路由的静态目录数字代替用户实际配置。

本次仅从既有测试网关的公开 `/v1/models` 读取所选 `opendesign/deepseek-v4.1-flash` 元数据：context 1,048,000、max output 328,000、reasoning=true、low/high/max。没有读取用户生产模型配置或凭据，也不宣称该声明证明用户生产 profile 的具体 override。

## 修复

1. 普通真实验收从当前所选网关模型条目取得上下文、最大输出、输入模态与思考能力，不再按场景制造 4096/16384。缺失输出声明时明确失败，不猜上限。报告记录目录来源、时间、声明值与隔离配置值。实际请求体另作核对。
2. 显式 `--responsiveness-output-pressure` 保留独立 4096 压力覆盖，证据单独存放，仍执行六类不同真实任务。此模式要求实际触发空答或截断并发生恢复，核对诚实终态，不把正常配置跑失败当作压力成功。
3. 原生失败收据入库与派发线程生成恢复决定之间存在窗口。旧代码会立即启动最终审核，甚至可能在恢复计划落地前关闭事项；本次真实旧证据中两次审核被新执行取代后永久保留 `running`。现在队列管理的失败执行必须先取得持久恢复决定，才可能进入最终审核。
4. 原始团队执行使用独立恢复链路，不受普通队列门禁误拦；队列派发的团队接续仍遵循该门禁。覆盖团队 owner-summary 恢复穷尽与已有可复用成果两种路径。
5. 被取代的审核标为 `superseded`；暂时暂停的孤立 running 审核回到 queued，不清除既有 queued 重试时刻和错误。恢复后可继续。未改成功判定、业务权限、模型设置或预算，没有新增用户确认。

## 验证

- 新行为用例在旧主线源码上实测失败：`failed receipt must not race recovery with a premature model review`；最终修复通过。
- 类型检查通过。相关专项通过：automatic-completion、automatic-recovery、team-service、team-recovery、phase3-partial-settlement、foreground-contract、no-quota、phase5-review、reply-segments、magpie-catalog。新增暂停/重试退避保护用例通过。CJS 语法与 diff 检查通过。
- 独立只读复核发现首版普通恢复门禁会卡住团队失败路径，已修正并新增行为用例；第二轮未发现阻断问题。
- 首版竞态修复、保持旧 4096 夹具的对照批次：六类前台、重连和独立取消通过，后台仍在 125.820 秒诚实失败；审核调用从原证据的 3 次变为 1 次。不是正常模型配置验收，不用其失败推断生产上限。
- **正常目录配置六类真实任务通过**：事实问答、计算解释、联网查询、跨会话记忆、生活计划、后台委托。Work 一次原生执行 completed、一次审核 delivered，97.173 秒 closed/succeeded，无遗留 running 审核。原生后台实际输出 6,458 tokens，其中推理 2,886；请求体的前台/后台/审核上限为 328,000，记忆提炼单独为 8,192。最终交付保留五天各上午/下午的材料、角色、验收与自查；审核纠正了原报告 20 个时段的计数错误为 36 个。
- **独立输出压力六类真实任务通过**：实际请求上限均为 4096；首个后台执行输出 4096 tokens（推理 2458）并在周四截断，定向恢复返回 3322 tokens（推理 1839）后 completed，最终一次审核 delivered，114.587 秒 closed/succeeded。失败祖先没有审核调用，无遗留 running；最终文字合并两段成果，并纠正时段计数。此批验证了截断恢复，不宣称每次压力批都复现空答；旧夹具对照已记录空答后诚实失败。
- 未为小改动重复跑全套门禁，未运行产品 build/打包、未重启生产、未进行崩溃注入。正常与压力测试都是实际 `pnpm dev`、隔离 HOME/profile、真实 renderer 和模型，不是原生指针输入或发行包验收。单批时长不是性能承诺。

## 仍需分开处理

产品辅助功能另有独立限额，不能宣称“产品完全没有硬帽”：HTML 片段编辑 4096、记忆提炼 4096/8192、页面回答 2000、来源核验 3000 等。既有报告记录过五次真实页面回答空答，以及后台记忆提炼空答/截断；仅凭历史记录不能把全部错误归因于上限。页面回答目前也未将 `stopReason=length` 的非空结果显式判作截断，这是单独的产品缺口。本提交没有扩大为这些功能的策略修改。

## 本机证据

隔离副本 `out/diagnostics/work-review-race/` 保存旧源码失败、最终专项、首轮 4096 对照与版本边界。正常最终批次在 `out/diagnostics/bot-responsiveness/live/`；独立压力批次在 `out/diagnostics/bot-responsiveness/output-pressure/`。报告包含模型声明来源、实际请求、逐次用量、六类延迟、重连与取消、Work 原生执行与审核状态。完整测试对话不提交。
