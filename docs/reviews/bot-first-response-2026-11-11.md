# Bot 首次回应与分段交付验收（2026-11-11）

## 目标与实现

解决“用户已发送消息，但要等搜索、工具和长篇生成全部结束才看到回应”的体验问题。收到请求、模型理解、工具已执行、最终结果是四种不同证据，不能相互冒充。

- 宿主受理后 **500ms** 仍无公开模型文字，写入一条独立、持久的 `receipt`。排队与处理中使用真实状态，不说已经查询、安排或完成；不启动模型来写这条回执。
- 500ms 前模型已有文字时不插入回执。模型文字到达后回执从显示中收起，保留元数据用于恢复与诊断，避免“收到”与具体承接重复。
- 同一模型原有调用中先给简短具体承接，再继续工具。每次公开输出按稳定 generation identity 保存为 `commentary` / `answer`，最终答案不覆盖此前承接，也不把 legacy `message.text` 额外显示一次。
- 工具状态独立于正文展示，只从实际工具事件产生。保留原有请求并发、取消、作用域、版本与终态保护。
- 最终收据可先于最后流帧到达，因此完成时从持久 transcript 重建当前请求的公开片段；不依赖最后一帧恰好送到。
- 冻结对话中的其他请求状态只代表取样时刻。无关的新问题不主动附带旧请求进度或送达承诺，确需说明当前状态时先查询。
- 追加展示元数据表，不提升应用 schema 版本，不清空旧会话。回执不进入模型答案文本，也不作为用户长期记忆。

## 真实模型与测量

复现入口：`pnpm -s test:bot-frontdoor:live --responsiveness`。可复用场景为 `scripts/bot-responsiveness-live-scenario.cjs`。

Omarchy，隔离 HOME/profile，实际 `pnpm dev` 与 Electron renderer，真实模型 `opendesign/deepseek-v4.1-flash`。不读取生产凭据、不修改生产数据、不重启生产实例，不运行产品 build/打包。

下面是最终批次的六种不同自然任务。除额外记忆写入夹具外，不用提示强迫模型说承接。计时起点为发送按钮的捕获阶段 click；首个可见文字由下一动画帧中的实际文本布局与视口相交观测。占位、工具状态、引用、指标、操作按钮都不算模型正文；宿主回执单列。数值单位为毫秒，单次批次不是 p95 或跨网络 SLA。

| 任务类型 | 可见宿主回执 | 首个模型正文 | 前台回复完成 | 前台模型调用 |

| 直接事实 | 595 | 2907 | 3028 | 1 |

后台委托行的“前台完成”表示委托回执完成，不是后台成果已经完成。后台成果、重连及取消检查的最终结果见下方。

宿主回执在本批次均低于600ms。模型正文仍需数秒，不能把回执速度当作模型推理速度。直接事实、计算、计划各一次原有前台调用；工具任务沿工具结果继续原有调用链，没有另启一轮只生成回执。自动记忆提炼、后台执行和结果审核的调用与前台计数分列，不隐藏其成本。

## 发现与纠正

1. 首轮仅加提示词与分段投影时，模型仍会跳过承接，记忆写入要等约8.7秒才出现正文。因此增加真实宿主回执兜底，而非声称提示词能保证快速首句。
2. 第二批六类的速度、持久化、后台结果与取消结构检查均通过，但人工复读发现无关追问仍说已取消的长回复“还在生成、完成后会出现”。保留该批次失败结论，补充旧状态边界并新增并发语义断言后完整重跑六类。
3. 工具前模型承接不是稳定保证，尤其记忆和后台委托可能直接调工具。模型未遵循时如实记录；可见宿主回执独立保证已受理的快速反馈。它不假装理解了具体需求。

- 独立只读代码复核未发现阻断缺陷；增加了复核提出的丢最终帧测试。
- 最终真实模型批次：六种回应指标、前台调用次数、重连与独立取消的结构/语义检查通过。取消后追问只回答“一周7天”，不再虚报旧任务继续运行。

- 非故障集成门禁：等待当前隔离验收进程退出后执行，结果另补记。

## 边界与证据

- 此优化降低静默等待，不承诺搜索、推理、长任务总时长缩短。宿主事件循环拥堵或断线仍可能影响回执送达。
- 供应商可能迟发文字或直接工具调用；不能承诺每条具体承接都在500ms内。
- 联网用例使用真实搜索；曾有官网原页被代理地址策略阻止，答案明确说明来源为搜索摘要。本项不等于所有实时事实完成独立核验。
- 中间批次后台审核曾遇到供应商仅输出推理而没有答案的错误，正常重试后收尾；不把工作者返回文本冒充后台已经成功关闭。
- 本机证据在 `out/diagnostics/bot-responsiveness/`。最终批次为 `run-3-stale-status-fix/report.json` 与 `completion-timeout-review.json`，超时时两个审核行仍running、attempt=1、error=null，根因未确认。`run-2-host-receipt/` 保留原自动结论及人工发现语义失败后的修订结论。
- 实测是实际 renderer/model 验收，不是原生指针输入或发行包验收。首轮进程编译后才补入最后帧对账代码，不能当作严格对照基线。完整测试对话不提交。
- 用户已有未跟踪的崩溃测试脚本保持不变。崩溃/故障注入按要求延期；正式聚合 runner 和失败 baseline 不修改。
