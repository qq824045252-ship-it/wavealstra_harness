# Work 团队使用方式

## 让主 Bot 根据现有 Bot 组队

也可以直接在对话中让主 Bot 组队，例如“用 @写作 和 @审阅 建一个内容团队，写作负责初稿，审阅负责核对”。主 Bot 会先读取当前用户已启用的现有 Bot 及职责，确认成员都是可用身份后保存为正式团队。组队这一步不会自动新建 Bot、修改成员配置或授予额外范围；如果缺少合适的 Bot，主 Bot 仍可按用户明确要求先用 `bot_organize` 创建（或用 `arrange` 调整配置），再把新 Bot 纳入团队。创建新 Bot 时可在 `configuration` 中同时选择 `skillIds`、`mcpIds`、`connectorIds`（以及模型、专家和工作目录），宿主会按真实可用目录校验后原子应用；不可用的能力会明确失败，不会静默挂上。团队名称在当前用户的团队中唯一，负责人固定为当前主 Bot。

组队工具只保存团队模板，不派发事项；真正开工仍需主 Bot 用 `work_team_create` 选择该团队并填写本次目标。普通 Bot 不能创建团队，应转由主 Bot 处理。用户没有明确要求组队时，主 Bot 不会自动建队。

## 从一个目标组队

在 Bot 模式顶栏选择「组队开工」。先新建至少两个 Bot，再选择主负责人和成员，填写共同目标、本地工作区绝对路径、每个人的具体分工、验收条件与全团队预算。

- 负责人负责最终核对与只读汇总，不兼任执行成员。
- 每个成员必须有明确分工。界面默认仅选择读取工作区；只有 Bot 已有写入权限时，才显示额外的工作区写入选项。组队不会扩大 Bot 自身授权。
- 默认仍按顺序执行，旧计划不会被静默改成并行。选择「按依赖并行」后，可设置最多 1–4 名在途成员，并为每人选择排在前面的成员作为前置依赖；不允许循环或未知成员依赖。
- 并行成员使用各自 Bot 身份、持久输入与执行记录。依赖表示等待前置执行和效果结算，不代表前置成功；失败结果也会如实传给依赖成员，不能假定失败步骤已完成。
- 独立成员可同时工作，但同一文件/目录写入仍遵循资源互斥，未知效果和未核实预算阻止新的阶段。负责人等待所有成员结算后只读核对与汇总，不越过验收。
- 分工面板显示调度方式、具体前置成员、等待结果/结算/并行名额的原因。模板保存调度方式和依赖，但不保存或授予新权限。
- 创建前可以关闭窗口，草稿不会执行；提交后关闭窗口不会停止工作。请在事项详情使用暂停或取消操作。
- 如果提交回执丢失，界面保留原请求身份，关闭、重开或刷新后仍可「核对原请求」，不会盲目再建一队。期间的较新导航不会被迟到回执替换。

## 看分工、结果和下一步

团队事项出现在负责人及参与成员的事项列表中。卡片注明 Bot 人数，事项详情直接显示团队状态、每人的职责、操作范围、实际执行状态与当前版本的协作记录。

「执行结束」不等于「目标已达成」。负责人汇总就绪后仍需通过既有成果评审与验收流程；失败、未知结果、未验证条件会保留，不按成员执行成功数量自动宣布完成。

若某个准备步骤尚未启动就受阻，详情可明确重试未启动的准备。已启动、部分完成或效果未知的执行不能通过该按钮重跑。

成员可以查看参与事项，在自己的 Bot 对话中讨论；参与身份不等于负责人身份，宿主仍校验控制操作和授权。

## 复用和管理团队模板

在组队窗口展开「将成员与分工保存为可复用模板」，填写名称保存。模板仅保存成员、负责人和分工配置，不保存本次目标、工作区、预算或新授权，也不会派发工作。下次使用模板时仍需重新核对成员状态与当前授权，并填写本次目标。

「管理团队模板」提供单独的删除确认。删除模板不会删除 Bot 或已经建立的团队事项。

这里的团队是围绕 Work 的可执行协作及可复用配置，不是独立于事项的无限聊天群；历史与结果始终归属于具体 Work。

## 验证口径

`scripts/bot-team-ui-test.tsx` 使用实际 React 输入、点击和生命周期处理，覆盖必要字段、最小权限请求、重复提交、断线重试、关闭及迟到回执、更新导航、连续建队、模板保存与删除、成员可见性。该测试不模拟桌面布局和原生焦点，不能替代真实桌面及原生 Durable 执行的端到端验证。

要求修改使原团队计划失效后，可以选择「按新要求只读复核」。界面保留原分工与原权限范围供核对，但新请求强制只读，不重做之前的写入或其他效果；历史成果不会自动满足新版本验收。每次要求、负责人或状态版本更新，都需要重新勾选确认。

## 当前边界

本轮完善的是可执行 Work 团队：有界并行、依赖结果交接、负责人统一汇总及恢复。它不是独立无限群聊或自动挑选/授权成员；外部渠道、桌面控制和任意 shell 不因并行而获得授权。任务级已授权范围和应用执行策略继续生效，越界操作仍需明确处理。实际在线模型的协作质量与打包应用验收需独立验证。

负责人交接后，摘要仅等待当前实际执行者，不再把旧分工消息中抄送的原负责人当成尚未返回的成员。按新要求只读复核时，会从新计划移除已成为负责人的成员和指向他的依赖，界面预览与提交保持一致；旧记录保留。
