## Dots 日常操作与审核边界

旧 Bot 有过一次具体故障：成员和负责人都已返回结果，事项仍挂着，用户还得采纳成果、手工结束。Dots 的日常委派从交办到收到结果，应当允许用户全程不再点一次确认。[旧 Bot 故障记录](reviews/bot-foreground-auto-judgement-2026-11-10.md)

| 环节 | Dots 的约定 |
| --- | --- |
| 操作权限（W02、W06） | 查询看板、绑定或改名指定空间、委派和改向都直接调用现有服务。删除 Dots 层的权限复核、审核员、审批卡和逐动作放行。服务自行检查任务归属、文件夹范围与暂停状态。遇到真实的系统授权或账号登录，只在需要用户操作时问一次。[应用内审批退役记录](work-action-approval-loop.md) |
| 事项收尾（W05、W07） | 一次性委派随原任务的真实结果收尾，持续事项保留下一步。日常交办不自动创建要求人工结项的 Goal。关联已有 Goal 时，本次成果可以先交付，原 Goal 的状态按其约定推进。只有用户明确约定由自己验收时，Dots 才等待该决定。[现有 Goal 结项契约](conversation-goal-continuation.md) |
| 普通产物（W06、W08、W10） | 直接展示当前要求对应的文件或文字。删去独立评审回合、评分、采纳或退回、逐文件「我已核验」和渠道签收。沿用普通消息的产物组件。若任务本身就是用户点名要的审稿，审稿意见就是该次产物。[普通消息产物实现](../src/renderer/src/components/chat/MessageItem.tsx) · [Goal 完成条件](../src/main/agent/ConversationGoalPrompt.ts) |
| 记忆与对话调度（W03、W04） | 偏好、决定与更正直接进入统一记忆。对话调度按适用范围读取当前版本，省掉「比对记忆 → 采用为独立草稿 → 来源变化后再复核」。常规写入和后台整理均无需用户逐条采纳。只有冲突确实影响眼前任务且无法从已有信息判断时，才问具体分歧。[对话读取记忆的实现](../src/main/agent/MemoryContextProjection.ts) |
| 改进与建设验收（W11、W12） | 独立回放、效果追踪和回退用于每周改进资产；端到端场景用于验收软件。两者都在日常交付之外运行。需要维护者处理的代码候选留在复盘里，用户照常收到本次成果。[原生会话每周复盘](native-self-improvement.md) |

日常交付的验收例子：用户交代「在客户 A 空间做一份报价单」后离开。普通任务返回本次的 `报价单.xlsx`，用户再打开 Dots 就能点开文件。期间新增的应用内审批、独立审稿回合、人工结项和签收操作均为零。若执行失败，Dots 沿原任务接续；确实缺少资料或业务决定时，只问缺的那一项。

## W02 对话与控制前台：小事当场办完

Dots 可以调用现有看板、空间和任务服务，在当前对话里办完查询、空间管理和对已有任务的控制。用户给出明确对象后，Dots 直接办理并回报结果。需要持续执行的工作交给对应空间的普通任务，Dots 继续接话和跟进。

| 用户交代 | Dots 当场做什么 | 用户看到什么 |
| --- | --- | --- |
| “报价做到哪了？” | 从看板定位事项，读取原任务的实际进度、成果和阻塞。 | 一句当前进展；已有成果可以直接打开。 |
| “找一下上周那份报价。” | 按空间和已有任务记录查找；若有两个合理候选，只问一个能区分它们的问题。 | 原任务入口。 |
| “把这个文件夹绑定到客户 A。” | 使用用户指定的目录和空间完成绑定，读回实际路径。重复交代时复用已有绑定。 | 空间名和已绑定的目录。 |
| “把这个空间改名叫华南客户。” | 对原空间改显示名，保留空间身份、磁盘路径和任务关联。 | 同一个空间显示新名称，原任务和文件仍可打开。 |
| “刚才那份报价，改成一个方案。” | 找到正在执行的原任务，向该次执行发送新要求并读取回执。 | 原任务的状态更新为“已排队”或“执行已收到”。任务完成后直接显示本次产物。 |

### 验收

上述五种操作均从 Dots 的正常对话入口完成，**新增普通任务数为 0**。用户只需交代一次，无须去看板转述指令。若用户在同一空间交办另一件独立的工作，Dots 可以在该空间新建普通任务。

已有绑定目录的空间也可以创建实际子文件夹。例如「在华南空间下建个新报价文件夹，在里面做报价」，Dots 先在指定父目录建立「新报价」并绑定同名子空间，再让普通任务在该目录工作。重复收到同一请求时复用子空间。

执行中改向沿用 A06：让原任务保持运行，从 Dots 发出修改，观察修改何时被原执行接收。端到端体验沿用 A20：用户在原对话一句话完成操作，并可在原事项找到处理结果。

## W10 日常界面

- **主页入口。** 打开 MyBuddy 主页，Dots 和普通任务就在同一份列表里。Dots 入口固定在「独立任务」分组正上方，即使还没有普通任务也可直接点击。
- **点开 Dots。** 主页保留任务列表，主区域显示 Dots 自己的对话。顶部是头像和名字，中间是消息，底部可以直接输入。文件跟随对应消息显示，点击沿用现有预览。[OpenAI 对话界面示例](https://images.ctfassets.net/kftzwdyauwt9/1xROyxcQu9wVqdHbbOjetz/4598e195e1e8acb11b66dd7f340fde12/introducing-dots-carousel-feedback.png?w=1280)
- **对话与任务切换。** 点击普通任务打开该任务自己的对话，再点 Dots 回到刚才的 Dots 对话。Dots 的对话调度器只服务于 Dots，长期记忆统一读写 Memory Kernel。
- **委派。** 如果 Dots 调用了普通任务，在 Dots 对话里显示一行任务名和当前状态。点击任务名可查看执行详情，任务运行期间仍可回到 Dots 继续说话。
- **看板与空间。** 全部事项沿用现有任务看板，空间与文件夹沿用现有侧栏。Dots 引用具体任务或空间时，名称可直接点开。执行记录留在原任务详情。

## W08 产物交付

Dots 先在原对话接单。普通任务完成后，Dots 在同一对话追加一条独立的助手消息。消息直接给结论，有文件就附上当次的版本。点击文件名沿用原有打开或预览方式。即使用户切去了另一任务，回来也能读到原消息和附件。

任务返回一个文件，就显示一个文件名，例如 **报价单.xlsx**。多个文件沿用普通产物列表。纯文字结果直接显示答案。交付到此结束，省去 Dots 评价、二次复核、用户确认按钮和完成总结。

## W05、W07 桌面主动跟进

| 发生了什么 | Dots 应当怎么做 |
| --- | --- |
| 原交办还有已授权的下一步 | 按最新要求在同一普通任务继续。已关联的 Goal 使用原有续办机制。 |
| 缺少必要资料或业务决定 | 把已有结果、阻塞原因和一个具体问题发回最初交办的对话。 |
| 执行失败或没有返回文字和文件 | 核对本次普通任务的执行记录。能够确认重试安全时限次补救，否则说明原因并询问下一步。 |
| 到达约定时间，或订阅的文件发生变化 | 从已登记的定时器或文件订阅接续。无变化保持安静，取消后停止。 |
| 回传前退出，或写完消息后来不及记录回执 | 重开后按这次委派的交付标识核对原对话，只补缺少的消息。 |

2026-11-22 的 Windows 桌面验收使用了两种模型。实际模型从「周转库」的 CSV 算出总数，原对话依次保留用户交办、接单和单独的助手消息 `236`。隔离测试模型用于稳定制造文件、阻塞和不可恢复的失败。五条主动回复在桌面重启后均保留原消息 ID。回传前和消息写入后分别中断时，每个普通任务各运行一次，恢复后各有一条结论。[真实模型聊天记录](../out/diagnostics/dots-handoff-live/2026-11-22T02-21-13-028Z/report.json) · [桌面事件及重开记录](../out/diagnostics/dots-proactive-desktop/2026-11-22T02-27-35-948Z/proactive-events.jsonl) · [断点、定时及取消记录](../out/tests/dots-reply-recovery.json)

交付目的地为桌面 Dots 对话。正式渠道账号投递及 A15 已按产品决定移出。A02 的跨入口私人身份与共享范围尚无实机验收结果。数据恢复遵循仓库当前格式策略。还原早期备份时，应按操作说明处理备份日期之后的遗忘。

最终验收仍需要独立案例中回答与来源同时达到 95%、连续七天运行，以及三类纠正在后续真实工作中的效果记录。生成案例、短时运行和脚本回放各自在上表对应的检查中计数。

11 月 22 日补齐个人记忆维护后，在 Windows、Core Ultra 9 285H、31.4 GB 内存上复测了十万条记忆和十万条持久向量。词法、混合检索以及完整 Dots 上下文装配的 p95 分别为 130、294 和 471 毫秒。60 个计时样本和 200 项合成正确性检查均通过，计时使用受控查询向量，剔除模型和网络耗时。另一次独立 LongMemEval-S 检索测量中，词法检索前五项在 200 题里有 154 题找齐标注来源，63 题同时包含答案原文。[规模回归记录](../out/tests/dots-memory-scale.json)

真实问答曾把另一个岗位的团队人数用来回答刚任经理时的人数。补充对角色、时间与事件的核对后，真实模型复测一题事实和两题拒答，三题均通过，其中一题是事先选定的留出题。不同轮次有波动。完整 200 题沿 Dots 原生问答入口运行，固定词法召回，单独记录答案、实际引用和需人工判断的自由表述。首次运行在第十题遇到模型下架，前九题单列。新批次固定了当前可用模型，进度保存在 `out/tests/dots-memory-longmemeval-answer-full-flash-2419-recovery.json`。
