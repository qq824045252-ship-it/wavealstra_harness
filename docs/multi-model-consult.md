# 多模型会诊

## 用途与边界

同一个任务交给设置中明确选择的不同模型独立分析，各模型的原始回答返回当前主模型，由主模型综合共识、分歧、独有发现和证据。适用范围不局限于代码 Review，也包括设计判断、故障诊断、方案比较和数据解释。

唯一执行路径：`主 Pi Agent → multi_model_consult → 独立只读 Pi AgentSession × N → 主 Pi Agent`。

不安装 pi-fusion，不引入第二套模型目录、认证或 Agent Runtime。不包含自动风险判断、生命周期 Gate、自动触发、Judge、Agent Team、DAG、后台续跑、递归会诊或自动 Debate。

## 配置与调用

1. 在 **设置 → 工具能力 → 多模型会诊** 启用，手动添加至少两个参与者：可以是**不同模型**，也可以是**同一模型的不同思考等级**（做推理强度对照）。**参与数量不设上限**，候选列表始终列出全部已启用模型，同一模型可以再次添加并自动落到它尚未使用的思考等级；只有「模型 + 思考等级」完全相同的重复项会被拒绝（它只会把同一个 worker 跑两遍）。模型列表与思考等级来自现有 Pi 模型体系；不自动选模，不把不可用模型替换成别的模型。每个参与者都会独立计费；只配置了 1 个模型时，设置页与能力状态都会标明这是同模型等级对照，不是跨模型验证。
2. 可设置最大并发、单模型超时、**单模型只读工具调用预算**（填 `0` 表示不限制）及是否允许读取当前任务授权文件。默认跟随 Pi 原有的逐模型思考偏好，也可为每个参与者显式选择其支持的等级。
3. 能力注册与其他现有内建能力保持一致，启用/关闭后的工具集合在**新会话**生效；每次实际调用会重新读取会诊配置，关闭后旧会话的调用也会被拒绝。
4. 输入框 **`+ → 多模型会诊`** 添加“多模型会诊 · 本条”标签。发送后标签清除；切换任务不会带到新任务。它向当前主模型提交明确请求，不从 UI 直接运行 Worker。
5. 也可以在自然语言中明确要求主模型调用 `multi_model_consult`。主模型可显式调用该普通工具，但没有任何代码层的自动触发策略。未调用此工具就不会运行会诊。

调用参数只有：

```ts
multi_model_consult({
  task: string,
  context?: string,
})
```

`task` 是完整且相同的分析任务；`context` 是必要事实、材料或证据。不会自动复制主会话历史、主模型结论或其他 Worker 的答案。所需文件路径与事实应明确写入任务/补充材料；不能假设子模型能看到主会话所有附件。

模型、并发数、超时、思考设置不由工具调用参数临时修改。

## 结果界面

主聊天流始终显示会诊卡片，不随普通执行时间线折叠。每个参与者显示等待、分析中、完成、失败、超时或取消状态；同一模型的多个思考等级分行显示，并在名称后标注思考等级与耗时（有 tokens 时一并显示），便于逐条对照。

详情是**浮动面板**而不是铺满视口的模态框：按内容高度伸缩、有上限、居中显示，窄视口（≤720px）自动回落为横向参与者标签条。拖动标题栏可移动面板（保留至少 120px 在视口内），双击标题回到居中；Esc 或右上角关闭。左侧是参与者列表（模型、思考等级、状态、耗时、tokens），右侧是共同任务、补充材料、该参与者的原始答案与真实工具记录。

点击详情可查看共同任务、补充材料、每个参与者原始答案以及真正发生的工具调用、参数与输出预览。不生成虚构执行轨迹，不显示隐式思维链。工具输出预览过长时明确标注截断；模型原始回答本身不截断、不经额外模型摘要。返回给主模型的结果同样标注思考等级；当参与者全部来自同一个模型时，结果里会明确写出「同一模型的不同思考等级是同一模型的两个样本，不构成跨模型交叉验证」。

**直接终止单个模型**：参与者处于「等待」或「分析中」时，卡片该行右侧与详情面板都会出现「终止」。它只结束这一个模型（报告状态记为「已取消」，原因写「用户终止该模型（未完成）」），其它模型继续运行，已收到的结果全部保留；尚未启动的参与者被终止后不会启动。整场会诊仍可用主输入框的停止按钮取消。

「基于此发现继续调查」把所选参与者的发现追加到当前主输入框，**不自动发送**、不恢复子会话。追加内容带会诊报告 id、参与者身份与状态、原始答案或失败原因，以及该参与者真实工具记录摘要（工具名、参数、输出预览）。失败的参与者只要有记录到的失败原因就同样可继续调查；只有在既没有回答也没有失败原因，或该会诊属于其它任务时按钮才不可用，并给出说明文字。用户编辑并发送后仍由主模型继续处理。

完整报告写入 Pi 工具结果的 `details.consult`；实时 IPC、历史回放及远程事件转发保留同一结构，避免普通工具 2,000/4,000 字预览规则截掉原始答案。

## Pi 0.87.1 接入

- 共用现有 `ModelRuntime`、认证及 `enabledModels` 范围。
- 每个参与模型使用 `createAgentSession`、`SessionManager.inMemory` 和独立 `SettingsManager.inMemory`。
- 独立资源加载器不加载磁盘 Extension、Skill、Prompt Template 或项目上下文文件。不存在第二层 Capability 暴露或递归调用。
- 使用 Pi 原生 `read / grep / find / ls` 工具定义；文件访问继承当前任务 `TaskFileAccessPolicy`，实际执行前解析真实路径并再次检查授权。
- 不开放 bash、PowerShell、write、edit、MCP 或代理派生工具。
- 子会话关闭自动重试、自动压缩和 cache warming；会诊结束或用户停止后释放会话。
- 子会话的逐次请求授权使用主会话当前 Pi 设置，私有模型/思考偏好不写回用户设置。

## 生命周期和限制

固定有界的并行调用，不做“直到模型一致”的循环。每个模型的只读工具调用预算默认为 24 次，可在设置中改为 `1`–`100000`，或填 `0` 表示不限制（此时只有超时或用户取消会停止该模型）；单模型超时可设 10–86,400 秒。参与模型数量不设上限，实际并发不会超过参与模型数量。

取消覆盖等待创建和正在生成两个阶段，并且可以只作用于**一个**参与者（界面「终止」）。未开始的模型不会在取消后启动；晚到的会话仅清理，不发送新模型请求。传输层清理的每一步（`abort`、`dispose`）都有独立等待上限，整体清理另有宽限上限：超过上限就按「清理未收敛」记录为错误并让报告结束，不会把兄弟模型或主界面永久挂住；被放弃的后台清理不能再改写已经终态的结果。

状态口径：全部成功为 `complete`，至少两个成功但未全部成功为 `partial`，只有一个成功为 `degraded`，零成功为 `failed`，取消未完成的会诊为 `cancelled`。用户终止单个参与者时该参与者记为 `cancelled`，整场口径按其余参与者的成功数计算（因此可能只是 `partial`/`degraded`）。所有结果已完成后的迟到取消不覆盖成功结果。

多数模型同意不等于结论正确；尤其要保留有证据的少数发现。多模型回答不替代真实测试、外部证据或用户授权。

本地/远端数据限制同样适用：提交的任务、补充材料以及各模型读取的授权文件内容会发送给对应模型供应商；调用按各供应商正常用量计费。此功能不是文件隔离沙箱，也不扩大主任务已有授权。

## 验证

离线契约、安全和持久化测试：

```bash
pnpm test:multi-model-consult
pnpm test:consult-card-ui      # 真实渲染：浮窗几何、参与者列表、继续调查、单参与者终止
pnpm test:consult-entry:desktop
pnpm test:builtin-capabilities
pnpm typecheck
pnpm build
```

`test:consult-card-ui` 在真实 Electron 渲染进程里加载真实的 `global.css` + 组件 CSS 与真实组件，断言面板在 1360×1000 与 420×820 下都不溢出、按内容高度伸缩、拖动与双击复位可用、三种参与者状态下「继续调查」都写入输入框且不含 `undefined`、以及终止按钮发出正确的 IPC 载荷。截图写入 `out/tests/consult-card-ui/`。

真实桌面与模型验收（需要有效认证，产生真实模型用量）：

```bash
pnpm build
MYBUDDY_CONSULT_MAIN='commandcode/deepseek/deepseek-v4.1-flash' \
MYBUDDY_CONSULT_SECOND='openai-codex/gpt-6-astra' \
pnpm test:multi-model-consult:live
```

真实测试创建隔离临时桌面配置，不覆盖日常设置。通过真实输入框/加号菜单发送，验证普通消息、代码阅读、多模型答案、工程计算、失败降级、取消、详情、刷新恢复和配置保存；结果写入 `out/tests/multi-model-consult-live/report.json`。测试结束删除临时认证副本。报告中 `PASS` 才表示整套真实验收通过，不能把离线测试通过当作真实模型通过。
