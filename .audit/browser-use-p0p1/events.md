# Browser page events integration

`BrowserPageEvents` takes the existing attached `PageInspectionSession`, exact `WebContents`, and task-authorized download directory. The caller must retain exactly one instance per WebContents and dispose it on tab destruction, session detach, task release, or shutdown. `await start()` before arming watchers. It never attaches, detaches, or disables shared debugger domains. Keep the instance while commands run; a dialog answer must bypass the action/presentation lock so it can unblock the original action.

- `snapshot(since)` returns bounded `events`, latest `cursor`, and `truncated`. A caller must treat truncated histories as incomplete. `armResponse({urlIncludes?, status?})` and `armDownload({urlIncludes?, filename?})` arm before dispatch; both watches provide `wait(scope)` and `cancel()`. Always cancel unused watches. URL criteria match the redacted URL: query, fragment and credentials are omitted.
- `setDialogRules([{type, answer, messageIncludes?}])` replaces one-shot rules. `currentDialog()` and `answerDialog(id, answer)` use the exact pending ID. A failed automatic response leaves the pending dialog available for manual response. Prompt default contents are not retained.
- Download routing checks exact originating WebContents and sets a randomized destination synchronously in `will-download`. Results distinguish completed, cancelled and interrupted; completed includes the actual path, byte count, and SHA-256. File paths originate from the trusted task directory, not website names. Pending downloads are cancelled on dispose or a failed wait.
- Network request/response/failure and console/exception events omit headers and bodies; URL credentials, query and fragment are removed, and obvious credential assignments in console text are redacted. Arbitrary page-supplied console messages may contain sensitive content in forms that cannot be reliably recognized; consumers must treat traces as potentially sensitive. Cursor buffers are in-memory, bounded, and per instance.
- The protocol interface accepts optional child session IDs for compatibility. This implementation enables and listens to the top target only; it does not attach, enable, or attribute out-of-process iframe sessions. Do not claim cross-origin iframe network diagnostics on this evidence. `will-download` checks originating WebContents regardless of which frame initiated it; iframe download behavior remains unverified.

Validation: `pnpm exec electron scripts/browser-page-events-electron-test.ts` with `ELECTRON_RUN_AS_NODE` unset passed using an isolated temporary Electron profile, a real local HTTP server, two real WebContents sharing one Electron session, a real `webContents.debugger` adapter, and actual file bytes. The probe covered foreign-WebContents download exclusion, completed-file bytes/hash, query and console redaction, automatic confirm and manual exact-ID dialog reply, response watch, cancellation, bounded cursor buffer, and that disposing the module leaves the debugger attached. `pnpm exec tsc --noEmit -p tsconfig.node.json --pretty false` produced no diagnostics in this module; the command output was filtered to this file, so this is not a repository-wide typecheck result. The registered `browser_exec` bridge, iframe/OOPIF events, interrupted downloads, and packaged app are not validated here.
