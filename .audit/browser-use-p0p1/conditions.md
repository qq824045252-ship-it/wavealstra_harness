# Browser conditions integration

`browserConditionSchema` and its derived `BrowserCondition` type define URL, text, value, count and state predicates. `browserConditionsScript(conditions)` validates up to 16 conditions and produces one fixed read-only script using `withBrowserDom`. Execute it against the already pinned, validated page/frame and pass the returned unknown value to `parseBrowserConditionEvidence`; verify the number of evidence entries equals the number of requested conditions. The parser uses TypeBox `Value.Check`. This module does not wait, sleep, retry, perform input, or decide action outcomes. The caller owns the common timeout, scope/page identity checks and polling loop.

`within` must select exactly one scope, crossing open shadow roots via the shared DOM helper. For text/value/state targets, multiple matching elements produce explicit ambiguous evidence. Count deliberately counts all matching elements within the unique scope. Missing targets satisfy `detached` and `hidden`, but other predicates fail. Unsupported checked/expanded state and invalid selectors fail with a reason rather than guessing. `match` defaults to equals; contains is explicit. Evidence contains `kind`, `matched`, bounded `observed` and `expected`, and optional reason; text values are truncated to 1,000 characters only after comparison. Password input values and their expected values are redacted, including failing comparisons. For missing or ambiguous value targets, expected is also redacted because target sensitivity cannot be established. Data URL observation is redacted to avoid including entire HTML. This does not make arbitrary page text or ordinary URL evidence non-sensitive; use the application's normal data handling policy.

Validation: with `ELECTRON_RUN_AS_NODE` unset, `pnpm exec electron scripts/browser-conditions-electron-test.ts` passed against a real Electron DOM in an isolated profile. It exercised URL/text/value/count, visible/disabled/checked/editable/expanded/detached states, Chinese text, open-shadow target within scope, ambiguous target and scope, invalid selector, password redaction, and TypeBox rejection of invalid input/output. The test bundles the module in memory using esbuild and directly executes the resulting read-only DOM script; it does not exercise the registered `browser_exec` tool bridge, frame mapping, or action/wait integration. Electron emitted GPU command-buffer shutdown messages after the PASS; process exit was zero. Filtering node typecheck output to `BrowserConditions` produced no module diagnostics, not a full repository gate.
