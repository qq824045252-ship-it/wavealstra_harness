# Browser file upload integration

Call `uploadBrowserFiles({ accessibility, context, selector, taskRoot, paths, scope })` using a host-derived task root, the selected pinned `BrowserDocumentContext`, and the exact ref returned by an earlier observation. One to 20 paths are resolved by `realpath` under the canonical task root, checked as regular files, and converted into canonical paths, names and sizes. Paths outside the root, including through a junction/symlink, fail before dispatch. `BrowserAccessibility.setFiles` is an internal execution primitive; call it only through the validated wrapper. It uses the observer's existing protocol owner and exact Runtime context, verifies the current document and observed ref, checks file-input type/disabled/multiple, and passes the matching object ID to `DOM.setFileInputFiles`. It then checks that the same connected input still has the expected FileList names and byte sizes. Only then does it set `scope.confirmed`; failure after dispatch has unknown effect and must not be blindly retried. Return value contains names and sizes, not local canonical paths.

Context/frame identity and task ownership must still be validated by the caller; the exact DOM object belongs to that one document. The external contract must not accept a caller-chosen task root or an arbitrary CSS selector in lieu of an observed ref. This module does not submit the form; that is a separate user action. As with path-based OS APIs, another local actor with write permission can replace a canonical file between filesystem validation and Chromium's file read. FileList size/name verification cannot detect a same-size replacement; no file-descriptor binding is available through the used CDP command.

Validation: `pnpm exec electron scripts/browser-upload-electron-test.ts`, with `ELECTRON_RUN_AS_NODE` unset, passed using an isolated profile, actual `PageInspectionSession`, `BrowserAccessibility`, main frame and a cross-origin out-of-process child frame. The probe observed real nodes, uploaded one file in the main document and two files to an open-shadow input in the child, read the actual File contents, and submitted multipart data to a local HTTP server that received both original byte sequences. It rejected a stale replaced node, unobserved target, multiple files on a single-file input, external absolute path, and external junction before `scope.dispatched`. Existing `pnpm exec electron scripts/browser-accessibility-electron-test.cjs` passed all AX, nested frame, lifecycle and shared-inspector cases. `node scripts/typecheck-scripts.mjs` passed with zero new errors, and filtered node typecheck showed no diagnostics in the new modules. The registered browser tool bridge and packaged app were not tested by this probe.
